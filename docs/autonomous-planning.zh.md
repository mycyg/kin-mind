# 记忆驱动的自主计划

Kin 在现有评估中，用 DeepSeek Flash / high 结合共同记忆、最近四轮带时间的公开聊天、心事、作品、探索结果、分享回执与当前计划决定下一步。分数供判断参考；启用 `semantic_actions` 后，候选、领取、发送前检查都使用有效的 DS 决策，取消 75 分门槛。免打扰、联系偏好、用户工作优先及渠道授权继续生效。DS 不可用或依据过期时等待复核。

情绪分数与短期动力目标继续根据有来源的新聊天、记忆和结果升高或回落，并按既有半衰期随时间变化。DS 可用 `action_decisions.strength`（0—100）调整步骤愿望强度，等待或放弃时也能调整。未填写时保留已有愿望强度；新愿望参考当前动力，不固定赋分。高分、低分本身都不决定执行权限。

计划保留稳定 ID、版本、目标、动机、来源和下次复核时间。步骤包含执行者、完成依据、依赖、前置条件及新加坡时间窗口；执行者可以是探索、创作、联系或用户。长期目标没有七天过期限制。到期、窗口开启或错过、相关新聊天与来源变化触发复核。重启不会把错过的安排集中补发。

复核按边沿触发：到期时间、计划来源变更或被取代、用户新消息、智能体版本变化、就绪步骤不能再按原决策执行——每个不同的原因唤醒一次复核，随后记入 `mind_plan_wakeups`。原因持续为真不再唤醒；多个原因同时成立也只用一次复核。尚未读取计划就被搁置的复核，其原因重新开放；已经读过计划的复核视为已回答。`decide` 写入当前智能体版本，配置升级只复核一次，不再每个宿主分钟唤醒一次。

DS 提议执行、等待、放弃及用户答应／完成／拒绝；宿主在事务中核对证据、版本与租约。用户参与通过 `owner_request_id` 关联心事，提出、已发送、已答应、已完成分别保存。模型不能用“已完成”替代执行或交付回执。

宿主还记录本次评估实际看到的计划视图，只有目标步骤的版本、状态与决策编号仍然一致，且该决策依赖的依据未变时才应用：步骤定义、各依赖步骤的版本／状态／回执、计划目标、动机、证据版本以及用户消息轮次。失去该栅栏的决策被搁置而不是报错——`plan-inactive`、`view-missing`、`step-touched` 或 `basis-changed` 随提交结果记录，本次评估其余部分照常提交，并合并为一次复核重新询问。因此过期的 `wait` 不能覆盖更新的 `execute`。只有在步骤与依据可证明未变时才重定基线；重定基线的决策不能推迟它没看到的那个版本已经要求的复核。没有记录视图时，仍以精确版本为唯一凭据。

与已存决策完全相同的 `wait`——动作、强度、已选交付文件、方法与前置条件说明都不变——写入 `mind_plan_reviews`，只推进下次复核时间：不消耗计划版本，因此不会使其他评估的预期版本失效，已存决策继续有效；强度等业务字段有变化时仍走原路径并提升版本。完成的复核为它看到的每个计划登记智能体版本，包括决策被搁置的计划；无法展示的计划不登记，其唤醒原因保持开放。不在未来的复核时间按未填写处理：决策退回到 20 分钟后，计划变更则立即复核；模型给出的原值保留在审计记录中。

探索执行器收到具体问题、实际记忆摘录、已有结论、缺口和最近聊天。当前执行器是 codex-cli，经专用本地网关调用 DeepSeek（deepseek-flash，推理强度 high）；回执分别记录执行器与模型提供方，消费者不得再按 provider=="kimi-cli" 过滤。独立创作执行器使用当前工作模型，在隔离目录中制作与计算；不恢复手机会话，不加载它的 MCP，不直接发送或修改共同状态。初始允许一个探索器与一个创作器，用户工作到来时保存进度并让路。宿主核对文件范围、大小、哈希、可检查的内容及 DS 完成复核。后续联系决策用 `artifact_hashes` 选择已核验文件，经原有持久发送链路交付；不确定发送沿原编号核对。

启用后，探索器可通过宿主持有的 `kin_ui` 接口使用 Codex Computer Use。DeepSeek 只接收新鲜的辅助功能／DOM 文本，不接收截图，并负责选择语义动作。宿主只暴露固定工具、当次运行新建的浏览器标签页和配置中精确列出的原生应用。每一次交互都由另一条固定 profile 的 DeepSeek／high 复核实际效果；可选的精确控件授权只作为复核提示，不能绕过复核。回执绑定完整原始快照哈希、精确控件行与输入版本，宿主在执行前再读一次完整界面。执行模型换一种说法不能自行生成权限。原生 Computer Use 的批准回执还要与应用 bundle id 和动作一致。默认不授权外部消息、付款和破坏性效果。配置及已经实际验证的边界见[电脑探索](computer-exploration.md)。

## 接口与开关

| 接口 | 用途 |
| --- | --- |
| `read_autonomous_plans` / `GET /v1/autonomy/plans` | 按范围、状态和 ID 分页读取计划、历史、版本及等待原因。 |
| `manage_autonomous_plan` / `POST /v1/autonomy/plans` | 创建、更新、暂停、恢复、改期、取消；写入要求幂等命令、来源、理由，修改需预期版本。 |
| `read_procedure_memory` / `GET /v1/autonomy/procedures` | 读取方法、依据和当前有效性，由 DS 判断适用性。 |

执行的领取、续租、结果及恢复接口限宿主使用。数据库采用增量迁移；模型在写事务外调用，提交时复核证据与租约。旧愿望按原身份迁移，不因迁移取得执行许可。

`mind_plan_reviews` 记录不构成版本的复核——重复的相同等待，以及完成复核登记的智能体版本——并保留其原因、决策与提供方回执；`mind_plan_wakeups` 为每个已回答的唤醒原因保留一行。两张表按需创建，其他代码不读取，旧版本宿主会忽略它们，回退时原样保留即可。

`semantic_actions`、`autonomous_plans`、`creative_execution`、`usage_reinforcement`、`procedure_learning`、`reinforcement_ranking` 独立控制，默认关闭。回退关闭对应路径，保留新聊天、计划历史、文件、来源和发送回执。

`plan_review_record_only` 属于记忆配置中的独立优化开关，默认开启；只有通过 `configure-memory` 显式设为 `false`，才恢复“每次重复等待都提升计划版本”的旧行为。边沿触发的唤醒、记录的计划视图与被搁置的决策不受该开关影响，始终生效。

## 使用加固与经验复用

明确查询、实际回复引用和已核验任务结果可以增加使用频次。同一输入跨端只计一次，同一计划的多步读取共用一次使用标识。后台扫描、候选命中、自动注入、摘要与规划不加热。频次按 30 天半衰期衰减，再取 `log1p`；不会提高事实置信度或恢复旧事实。

频次记录先启用，排序先试算。新权重有独立版本和真实开始时间；至少七个连续观察日、满七天、同版本回放合格且用户决定后，才可开启排序。旧冷热规则的试算时间不能替代这次观察。

方法记忆保留适用条件、步骤、工具与环境版本、成功标准、失败反例和实际结果来源。候选经过两个不同案例的隔离回放才可启用；外部效果使用既有真实回执，不向手机重复发送测试。更正、反例、配置或依赖变化使方法待复核。方法没有改写人设或扩大权限的能力。

## 效率与验收

关键词、向量和关系候选并行读取；不同事件可并行生成摘要，同一事件仍只有一个有效生成任务。所有模型调用共用一份数据库准入台账，通道按调用方声明的用途划分，后台并发可配置 1—8；通道与各类等待见下文。结构化判断以整份渲染后的请求连同它所回答的那个判断为键，只有调用方报告自己校验通过后才可复用，最多存活五分钟，所依赖的来源、记录或图谱对象一变即作废。缓存复用、实际模型用量和未知用量分别记录；命中记为一次复用调用，不计入新的 token 消耗。超时不算零成本，迟到结果不能提交有效状态。

普通聊天复用现有输入分类中的召回决定，不固定新增一次模型请求。主动补读最多三轮、150 秒，单次重排最多 30 秒；失败返回本地有效证据及缺口。自动背景保持原预算。

运行 `pytest -q`、`node --test adapters/*.test.mjs`。私有发布验收保留冻结的 48 个历史案例，关键案例须 21/21，一般前八命中至少 44/48；另跑规划语义案例、并发和中断测试。约一万条记录的温缓存本地候选 P95 目标为 500 毫秒，网络与模型耗时、总 token 单独报告。私聊、回放原文、私人计划和凭据不进入公开仓库。

设计参考 [CoALA](https://arxiv.org/abs/2309.02427)、[Mem0](https://arxiv.org/abs/2504.19413) 和 [Snowflake 的上下文层](https://www.snowflake.com/en/blog/agent-context-layer-trustworthy-data-agents/)。这些资料的特定实验收益不代表 Kin 已获得同样收益。

## 回复、等待与当前步骤核验

整组公开回复通过 `share-preflight-group` 一次交给 DeepSeek high 判断，包含对应用户原话、最近公开对话、来源与发送历史。返回整组允许、修订或待复核，以及每个原气泡编号。审核暂缓不算已送达；只有真实的 `choose_reply` 回执能表示不回复或合并输入。发送前冻结整组正文，重启后核对原消息编号，部分发送不重新改写。健康检查按输入编号结算，模型切换通知和旧回复不消除新输入的等待。

一次调用装不下的长回复改为分段审核，不再直接拒绝。每段最多 48 个气泡或 120,000 字符，且不切分气泡，所以单个超长气泡自成一段。每段都带上整组按次序的提纲、前面各段已作的判断，以及整组引用发现的并集；每段必须按次序只返回本段的气泡，遗漏或重排的一段会被拒绝，也不会入库。一段判完立即写入 `mind_reply_review_chunks`，因此崩溃、拒绝或宿主自身超时都不会为同一段付第二次钱。两个边界以普通的待复核理由出现，而不是失败：超过十六段的回复报告 `reply-exceeds-review-capacity`，宿主可以据此退役该组；审核超出 150 秒时限则停在段边界，报告已完成的段数与总段数，下次继续只为剩下的部分付费。合并回执保留每一段自己的计量；某段没有报告用量时记为未知，绝不记为零。

上一组回复被打断时，它尚未发出的条目随下一组回复的审核作为 `remainder` 一同送达。审核在 `covers_remainder` 里写明本组已经讲清楚的条目，以及承接它的气泡；没有提到的条目作为 `remainder_owed` 返回，继续挂着等待。被承接的条目把内容预留交给承接它的气泡，没人承接的条目继续持有它仍欠着的内容。已经发出一部分的组永不改写：已发出的气泡只作语境，永不改写、永不重发，只判断尚未发出的部分；不能照原文发出的剩余部分改为待复核，由宿主退役后另起一组。开关是 `chunked_reply_review`；关闭后恢复单次调用的限制，超出的组被直接拒绝。

后台容量通过 `configure-model-capacity` 配置，跨进程共用，范围 1—8；宿主启动时也会把配置文件里的 `background_model_limit` 写到同一处。未配置时仍按 2 准入，但会写 `model_capacity_unconfigured` 指标，状态里报告 `source: "default-unconfigured"`，不会静默回落。准入按调用方声明的用途分三条通道：后台、不受前台让路影响的用户工作保留名额、以及总是准入只做记录的前台，详见[模型通道](kin-mind.md#model-lanes-and-the-lease-interface)。请求尚未准入时，容量和前台让路单独计数并退避，不消耗失败次数。真实错误、已经发生的调用和不确定用量仍保留。恢复操作限定有来源的任务清单，保留原编号与历史，重新读取当前来源。

制作完成核验分别保存当前步骤缺口 `step_remaining`、后续事项 `downstream` 和建议 `advisory`。旧 `remaining` 兼容为当前步骤缺口，执行器的说明由 DS 分类。缺少核验时保留产物、工作目录、`needs_verification` 阶段及具体恢复动作。后续交付与用户回应分别结算，不增加额外批准条件。

可选的宿主静态 HTML 核验在受限子进程中生成手机和桌面宽度截图，禁止页面脚本、外部网络、本地外部资源、下载与服务工作线程。宿主复核原文与截图哈希及 PNG 尺寸；截图说明渲染实际发生，不代替独立审美检查。整组审核和渲染器可独立关闭，保留已有消息、产物和回执。
