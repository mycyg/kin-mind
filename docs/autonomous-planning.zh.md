# 记忆驱动的自主计划

Kin 在评估中确立目标、复核行动。宿主配置设置了 `main_session_review` 时，由主会话自己的模型评估——默认在经 `_kin/assess` 建立的临时只读分叉中进行，`assessment_channel` 为 `legacy` 时则是会话内的一次安静回合；否则由 DeepSeek Flash / high 评估。共同记忆、最近四轮带时间的公开聊天、心事、作品、探索结果、分享回执、计划与可用能力都进入这次评估。分数只是判断依据，从不是执行门槛。缺少决策或依据过期时等待复核。

情绪分数与短期动力目标根据有来源的新聊天、记忆和结果升高或回落，并按配置的半衰期随时间变化。评估可以用 `action_decisions.strength`（0—100）调整强度，等待或放弃时也可以。未填写强度时保留愿望当前的强度；新愿望参考当前动力，不固定赋分。高分、低分本身都不授予或撤销执行权限。

默认情况下，分数既不限制联系，也不限制探索：固定的 75 分门槛只在 `legacy_drive_thresholds` 打开且 `semantic_actions` 关闭时生效。启用 `semantic_actions` 后，候选、领取和发送前检查都要求一个经过核验的当前决策。免打扰、当前联系偏好、用户工作优先、渠道授权以及来源／版本校验起决定作用。普通聊天复用输入分类给出的 `recall` 决定，不固定新增一次模型请求。主动补读最多三轮、150 秒，单次重排最多 30 秒；可选步骤失败时返回已核验的本地证据与明确缺口。

计划保留稳定 ID、版本、目标、动机、来源、下次复核时间和步骤依赖图。执行者可以是 `explore`、`create`、`contact` 或 `owner`。每个步骤记录目标、完成依据、新加坡时间窗口、前置条件、输入及可选的 `owner_request_id`。长期计划没有七天过期限制。时间窗口开启或错过都会触发复核。重启不会把错过的安排集中补发。

复核按边沿触发：到期时间、计划来源变更或被取代、用户新消息、智能体版本变化、就绪步骤不能再按原决策执行——每个不同的原因唤醒一次复核，随后记入 `mind_plan_wakeups`。原因持续为真不再唤醒；多个原因同时成立也只用一次复核。尚未读取计划就被搁置的复核，其原因重新开放；已经读过计划的复核视为已回答。`decide` 写入当前智能体版本，配置升级只复核一次，不会每个宿主分钟唤醒一次。

评估提议计划变更，以及 `execute`、`wait`、`abandon`、`owner_accepted`、`owner_completed` 或 `owner_declined`。宿主在评估事务中核对所附来源清单与预期版本。用户参与需要真实的用户来源；提出、已发送的邀请、答应与完成分别保存。模型不能替 Kin 结清执行，也不能凭空生成渠道回执。

宿主还记录本次评估实际看到的计划视图，只有目标步骤的版本、状态与决策编号仍然一致，且该决策依赖的依据未变时才应用：步骤定义、各依赖步骤的版本／状态／回执、计划目标、动机、证据版本以及用户消息轮次。失去该栅栏的决策被搁置而不是报错——`plan-inactive`、`view-missing`、`step-touched` 或 `basis-changed` 随提交结果记录，本次评估其余部分照常提交，并合并为一次复核重新询问。因此过期的 `wait` 不能覆盖更新的 `execute`。只有在步骤与依据可证明未变时才重定基线；重定基线的决策不能推迟它没看到的那个版本已经要求的复核。没有记录视图时，精确版本是唯一凭据。

与已存决策完全相同的 `wait`——动作、强度、已选交付文件、方法与前置条件说明都不变——写入 `mind_plan_reviews`，只推进下次复核时间：不消耗计划版本，因此不会使其他评估的预期版本失效，已存决策继续有效；强度等业务字段有变化时走常规路径并提升版本。完成的复核为它看到的每个计划登记智能体版本，包括决策被搁置的计划；无法展示的计划不登记，其唤醒原因保持开放。不在未来的复核时间按未填写处理：决策退回到 20 分钟后，计划变更则立即复核；模型给出的原值保留在审计记录中。

探索执行器收到具体问题、实际记忆摘录、已有结论、缺口和最近聊天。它运行当前运行时包里的 Codex（或显式配置的 `native_codex_command`），经专用探索网关调用 DeepSeek——`exploration_model` 为 deepseek-flash，`exploration_reasoning` 为 high；回执把执行器记为 `codex-cli`，并单独记录模型提供方。创作器在 `creation_directory` 下的隔离工作目录中运行同一个 Codex，使用 `creation_model`（默认 `gpt-6-sol`）与 `creation_reasoning`（默认 `medium`），只有路由配置的 `workFast` 打开时才请求 Fast；它的原生执行回执必须写明这个模型。创作器不恢复手机会话，不加载 MCP 工具，不联网，不发送消息，也不写共同状态。同一时间各运行一个创作器和一个探索器。用户的新消息不会让它们停下：宿主告诉 Kin 当前在运行什么，由她决定；宿主只在关闭时或用户明确说出停止指令时结束它们，用户工作繁忙只会阻止新的运行开始；被停止的运行保留工作目录和检查点。宿主核对文件范围、大小、哈希、可检查的内容以及单独的 DeepSeek 完成复核。交付需要之后的评估决策用 `artifact_hashes` 选定已核验文件，再经持久发送链路送出；不确定的发送沿原编号核对。

启用后，探索器可通过宿主持有的 `kin_ui` 接口使用 Codex Computer Use。探索模型只接收新鲜的辅助功能／DOM 文本，不接收截图，并选择语义动作。宿主只暴露固定工具、当次运行新建的浏览器标签页和配置中精确列出的原生应用。没有第二个模型复核交互：执行器声明交互类别，宿主套用用户的硬性规则。发送或发布、付款、删除、凭据与系统控制一律拒绝；标签本身指向这些操作的目标，或未声明的类别，会连同原因退回；本地写入需要宿主为写入限定的目标。执行前宿主重新读取目标，目标必须仍显示预期的元素与标签。原生 Computer Use 的批准只接受针对已授权应用与动作的同一低风险请求。配置与限制见[电脑探索](computer-exploration.md)。

## 接口与开关

| 接口 | 用途 |
| --- | --- |
| `read_autonomous_plans` / `GET /v1/autonomy/plans` | 按范围、状态和 ID 分页读取计划、历史、版本及等待原因。 |
| `manage_autonomous_plan` / `POST /v1/autonomy/plans` | 创建、更新、暂停、恢复、改期、取消；写入要求幂等命令、来源、理由，修改需预期版本。 |
| `read_procedure_memory` / `GET /v1/autonomy/procedures` | 读取方法、依据和当前有效性，由评估判断适用性。 |

执行的领取、续租、结果、中断、恢复与延期接口（`plan-claim/renew/result/interrupt/recover/deferral`）限宿主使用，不作为模型的完成工具。恢复只收回租约已过期的执行，其余列在 `still_leased` 下；未启用 `liveness_checks` 时要求工作进程已经停止。数据库采用增量迁移；模型在写事务外调用，提交时复核来源、版本与租约。愿望按原身份迁移，不因迁移取得执行许可。

`mind_plan_reviews` 记录不构成版本的复核——重复的相同等待，以及完成复核登记的智能体版本——并保留其原因、决策与提供方回执；`mind_plan_wakeups` 为每个已回答的唤醒原因保留一行。两张表按需创建，其他代码不读取，回退时原样保留即可。

`semantic_actions`、`autonomous_plans`、`creative_execution`、`usage_reinforcement`、`procedure_learning`、`reinforcement_ranking` 独立控制，默认关闭。生命周期与冷热开关保持各自的含义。回退时关闭对应路径，保留新聊天、计划历史、文件、来源和发送回执。

`plan_review_record_only` 属于记忆配置中的独立优化开关，默认开启；通过 `configure-memory` 显式设为 `false` 时，每次重复的相同等待都会消耗一个计划版本。边沿触发的唤醒、记录的计划视图与被搁置的决策不受该开关影响，始终生效。

## 使用加固与经验复用

明确查询、实际回复引用和已核验任务结果可以增加使用频次。同一输入跨端只计一次，同一计划的多步读取共用一次使用标识。后台扫描、候选命中、自动注入、摘要与规划不加热。频次按 30 天半衰期衰减，再取 `log1p`；不会提高事实置信度，也不会恢复已更正的事实。

频次记录与排序分开。打开 `usage_reinforcement` 即开始该权重版本自己的观察；只有同时满足以下条件，才允许开启 `reinforcement_ranking`：自开始起满七天，该版本有连续七个实际观察日，且 `reinforcement_validation` 写明同一权重版本、带有用户批准、评估时间在这七天之后，并指向冻结回放的输出文件及其 SHA-256。该回放必须至少有 48 个案例，21 个关键案例全部命中前八，且至少 44 个案例命中前八。冷热试算不能替代这次观察。影子指标记录排序差异，生产顺序不变。

方法记忆保留适用条件、步骤、工具与环境版本、成功标准、失败反例和实际结果来源。在两个不同的已记录案例通过隔离回放之前，它一直是候选。外部效果使用真实的已有回执，测试不向手机重复发送。来源更正、反例、智能体配置变化或环境版本不可用都会阻止当前执行。方法不能改写人设或扩大权限。

## 效率与验收

关键词、向量和关系候选并行读取；同时最多运行两个事件摘要，同一事件从不同时生成两份。所有模型调用共用一份数据库准入台账，通道按调用方声明的用途划分，后台并发可配置 1—8；通道与各类等待见下文。有前台租约时，任务工作进程只领取不调用付费模型的任务。声明了判断的结构化结果，以整份渲染后的请求连同该判断为键缓存，只有调用方报告自己校验通过后才可复用，默认存活五分钟（调用方可以声明其他有效期），所依赖的来源、记录或图谱对象一变即作废。命中记为一次复用调用，不计入新的 token 消耗。超时请求的用量记为未知，迟到的用量回执与有效结果分开保存。

运行 `pytest -q`、`node --test tests/business/*.test.mjs`。合成规划案例覆盖长期目标、时间窗口、依赖环、用户参与、变更、重启、并发、部分交付和模型不可用。冻结的 48 个历史案例回放是上文频次排序的门槛。温缓存下的本地候选 P95 与网络、模型耗时及总 token 分开测量。私聊、回放原文、私人计划和凭据不进入 Git。

设计参考 [CoALA](https://arxiv.org/abs/2309.02427)、[Mem0](https://arxiv.org/abs/2504.19413) 和 [Snowflake 的上下文层](https://www.snowflake.com/en/blog/agent-context-layer-trustworthy-data-agents/)。这些资料的实验收益不代表 Kin 已获得同样收益；原始证据、带版本的视图与可回退的状态是系统的依据。

## 回复、等待与当前步骤核验

普通聊天与娱乐回复经格式整理后直接交给持久发送器，不经过审核模型。已分享的内容在生成时作参考，不否决发送。主动联系复用评估的决策，并重新检查当前联系条件。Kin 明确的 `choose_reply` 决定——`silent` 或 `merged`——照常有效。

无法照原样发出的正文——带有内部标记或损坏的封装，或被宿主标为需要修复——会被撤回，不重新生成，也不改写。Kin 的下一次用户回合会得知它没有发出（不附原文），由她决定怎么说。不重做工具与已完成的工作。部分发送保留已送达的内容，不确定的发送沿原编号核对。

后台容量通过 `configure-model-capacity` 配置，全库共用，范围 1—8；宿主启动时也会把配置文件里的 `background_model_limit` 写到同一处。未配置时按 2 准入，但会写 `model_capacity_unconfigured` 指标，状态里报告 `source: "default-unconfigured"`，不会静默当作已配置。准入按调用方声明的用途分三条通道：后台；不受前台让路影响、也没有调用方声明的用户工作保留名额；以及总是准入、只做记录的前台，详见[模型通道](kin-mind.md#model-lanes-and-the-lease-interface)。未获准入的请求是不计次的等待，有自己的计数与退避，不消耗尝试次数。一次评估中的嵌套调用复用它已获准入的租约。真实错误、部分完成和不确定用量都会记录。有来源、有范围的仅准入恢复保留任务编号与历史，从不把旧提案当作新决策。

制作完成复核分别保存当前步骤缺口 `step_remaining`、后续事项 `downstream` 和建议 `advisory`。`remaining` 按当前步骤缺口读取；执行器的说明是 DeepSeek 完成复核的证据。缺少核验时，产物保留 `phase=needs_verification`、`verification_gaps`、检查点和恢复动作。复核返回后再核对一次产物哈希与当前证据。后续交付与用户回应是单独的步骤。

可选的 `CreationVerifier` 在受限子进程中使用宿主配置的 Playwright 模块与浏览器，以 390 与 1024 像素宽度渲染静态 HTML，禁用页面脚本、外部资源、网络、下载与服务工作线程。结果宿主再次核对原文与图片哈希及 PNG 尺寸。渲染证明输出与版式实际发生，不代替独立的审美检查；截图或失败的渲染都不能转成成功的检查。可选渲染器可以单独关闭，保留日志、原文和回执。
