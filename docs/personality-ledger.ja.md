# 特性台帳・表現の意図・行動検証

人格は長らく、誰も書き込まない項目でした。`traits` は空のままで、主張も予測も作る呼び出し元がなく、通常の評価が返した人格の提案は何も言わずに捨てられていました。もともと行われているその評価に、いま六つの任意セクションが加わります。それぞれに開閉スイッチがあり、共通の規則はひとつです。**ホストは、引用された材料が実在すること、与えられた種別を名乗るに足ること、互いに離れた時点から来ていることだけを確かめます。その文そのものを判定はしません。** Kin がどういう存在かという文は Kin 自身のものであり、ホストはその背後にあるものだけを保証します。

各セクションは任意で、既定では空です。スイッチを切ると、その項目・型定義・プロンプト段落は要求から取り除かれ、それでもモデルが返した値は誰かが読む前に空にされ、保存される提案からも省かれるので、前のリリースでもその行を読めます。拒否されたセクションは単独で拒否されます。同じ評価の気分・願い・計画判断は通常どおり確定し、拒否は `mind_section_refusals` に記録され、**そのために有料のモデル呼び出しが二度目に積まれることはありません**。次の評価は、そのセクションを持つ投影を通じて拒否理由を見ます。履歴レーン、追問、継続性の初期化、セッション保守は、これらのセクションをいっさい運びません。評価の実行中に相手がまた書いてきたときは `trait_observations` だけが確定し、判断と意図は次の回に回ります。

## 特性台帳

`trait_ledger` は `trait_observations`（1 回の評価につき最大 4 件）と `trait_decisions`（最大 2 件）、および `mind_traits` / `mind_trait_history` / `mind_trait_observations` / `mind_trait_dependents` の各表を有効にします。

**観察**とは、ひとつの経験から得られた、ひとつの特性を支持または否定する一件の証拠です。表は追記のみで、同一性は語り直した回数ではなく証拠そのものにあります。したがって、ひとつの特性は経験と極性ごとに観察を一件だけ取ります。ひとつのやり取りの窓に十件のメッセージがあっても、起きたことは一度であって十度ではありません。**経験**はホストのもので、優先順に、実行 id、相手の発言を三十分以内で結合する既存のやり取り窓、または発話の根から取られます。ひとつの発話がふたつの名前空間に取り込まれても、根はひとつ、経験もひとつです。呼び出し元は経験を統合できますが、ホストの経験を分割することはできません。

何が何の証拠になれるかは、本文を書いたのが誰かではなく、証拠種別が決めます。`owner_statement` は相手自身の言葉です。explicit の権威、user の役割、message の事象、相手の名前空間、generated でないこと、設定や自己認知の記録でないこと——設定や人格の来源も explicit を帯びますが、ここでは拒まれます。`verified_behavior` は Kin が実際に行ったことで、`result_ids` からホスト自身が解決した実行の受領として引用します。完了かつ検証済みの計画実行、検証済みのタスク結果、プラットフォームのメッセージ ID を伴う受理済みの送達、または完了した探索です。探索の報告そのものは Kin が書いたものなので `self_statement` にあたり、行動にあたるのはその受領です。`mind-internal-event` の来源はどの種別の証拠にもなりません。引用される証拠の ID は、この評価に渡された集合の中になければなりません。

特性は提案された瞬間から働きます。`establish` は、この共有された経験がそれを実際に帯びていると述べるもので、basis が `inference` のときは、互いに異なる経験が少なくとも二つ、Kin 自身の言葉ではない支持の観察が少なくとも一つ、そして経験の異なる観察を二つ名指してなぜ別なのかを述べることを要します。足りなければ `trait-single-episode` として拒まれ、候補はそのまま働き続けます。`owner_instruction` と `owner_correction` は、引用された材料がすべて相手の言葉の述語を通ること、`quote` が引用先の記録の逐語的な部分文字列であることを要し、取り消しは特性より古い証拠に依ることができません。取り消された特性は墓碑を残します——理由、終わらせた来源、そして読めるまま残る履歴です。同じ鍵をもう一度提案するには、墓碑より新しい相手の言葉が要ります。支持は、実効利用がすでに用いている三十日の半減期で減衰します。支持が尽きた特性は何かが書かれる前の時点で「薄れつつある」と読まれ、台帳の次の書き込みがそれを記録します。観察の下にある来源が動いた特性は `needs_review` になり、確認待ちの特性は成立ともみなされず、積み上げてよい候補としても示されません。

そもそもどの分類が育ちうるかは、承認された人格契約だけが決めます。中国語の分類名は、それが指すひとつの鍵として契約に届きます。評価モデルには最大 12 件の特性が、成立と候補に分けて示されます。示されるのは証拠の本文ではなく数——種別ごとの観察数と経験数、自述以外の支持、反例、またがった日数、すべてが一つの窓の中かどうか——に加えて、最大 6 件の訂正とそれぞれを終わらせた来源、そしてこの投影が持つ直近の拒否です。チャットモデルには同じ台帳が `self-traits` と `trait-corrections` という独立した項目として示され、basis はどちらも `self_knowledge` です。どれも相手が話しているのではないからです。スイッチを切れば両方とも消え、文脈は以前のままになります。

## 表現の意図

`expression_intent` は、同じ評価が次の数回の返事でどう居合わせるつもりかを述べられるようにします。姿勢がひとつ、続けたい話題が最大二つ、当面触れないことが最大二つ、そしてそれがどれくらい有効なつもりか（10〜720 分）です。これまでチャットモデルは、数値の落ちた位置で選ばれる固定文の対応表から Kin の状態を知るだけで、その場について実際に判断されたことは何ひとつ言葉づかいに届いていませんでした。

ホストが確かめるのは材料が実在することだけです。この同じ評価が受け取った証拠、台帳がいま示した版のまま保持している特性、この範囲が抱えている心配ごとです。解決できない引用は意図だけを拒み、理由は `trait-unknown`、`intent-concern-unknown`、`intent-evidence-unknown` のいずれかになります。姿勢が引用されることはなく、台本でもありません。どう居合わせるかを述べるだけで、言葉そのものは人格が決めます。名指された心配ごとは続けて扱うものの先頭に立ち、ID のない話題も重なる心配ごとを見つけます。

意図は新しいあいだだけ使われ、その後は決して使われません。終わるのは、自分の分数が尽きたとき、下にある証拠が動いたとき、引用した特性が書き換えられたか取り消されたとき、継続性が働いていないとき、人格が変わったときです。**相手からの新しいメッセージは意図的にそこに含めません。** あるメッセージへの返事は、そのメッセージを評価するより先に書かれるので、届いた時点で失効する意図はそもそも一度も使えません。成立しないどの場合でも、言葉づかいは対応表の答えへ一バイトも違わず戻ります。

## 評価が自分の動きについて述べること

`next_move_audit` は、ひとつの評価が「いま何をしているか」と「それが何に依っているか」を述べ、追記のみの `mind_next_moves` に記録します。これは監査であって、それ以上ではありません。**順序づけも、準備完了の付与もしません。** どの願いも、どの計画段階も、動きが記録されるようになる前とまったく同じに選ばれます。願いを読む側にも行動を組む側にも、この表の存在を知るコードはありません。

モデルが宣言するのは `reply`・`quiet`・`rest` の三語のいずれかで、より長い言い方はホストのものです。ホストは、提案されたことではなく、この同じ評価が実際に確定したもの——走らせた段階、望みのまま残した願い、相手に出した依頼——を読み、そこから `explore`・`create`・`invite`・`ask` を導きます。いま相手のもとへ向かうものをこの確定が始めているのに何も起きていないと述べるとき、またはこの評価が確定も維持もしていない願いや段階を指すとき、その動きは不整合です。名指したものをホストが見つけられないとき、その根拠は偽造です。根拠が名指してよいのは、この評価の証拠、台帳がなお保持している特性、いまも有効な心配ごと、台帳が記録した訂正です。どちらの過失もこのセクションだけを落とし、モデル自身の二文——検討した別の道と、その理由——は書かれたまま残ります。

## 行動検証の連鎖

`behavior_chain` は `self_hypothesis`（一件、予測は最大二つ、各予測に 1〜168 時間の検証窓）と `prediction_outcomes`（最大 3 件）を有効にします。ホストは仮説と予測をその評価自身のトランザクションの中で記録し、それがどの構成のもとで作られたかの刻印を添え、以後の評価には未決の予測を最大 4 件示します。

結果として受け入れられるのは、ホスト自身が解決したもの——検証済みの実行受領、またはこの同じ評価の explicit / operation 権威を持つ証拠——だけで、しかも予測が先であったときに限ります。同じ時刻は先ではありません。予測を立てた者にも見えていたからです。予測が当たったという Kin 自身の報告は、何も決着させません。

「同じ構成のもとで作られた」はかつて `agent_version` の一致を意味しましたが、この版番号は無関係な編集のたびに動くため、使われるまで生き延びた検証はひとつもありませんでした。いまは互換鍵です。承認された人格とその三つの本文のハッシュ、宣言定数 `BEHAVIOR_CONTRACT`、各次元の定義文（基準値と半減期は含みません。それこそが進化の動かすものです）、評価するモデルと応答するモデル、そして行動が依存しうる実行環境の部分からなります。無関係な版の更新では予測は検証可能なままで、実質的な変更のときだけはっきり失効し、どの成分が動いたかを示します。失効しても何も削除されません。行動に関わるプロンプト段落の要約は固定されており、それを編集した者が二つのうちどちらかを選ぶまでテストは通りません——契約を進める（以前の検証はもうこのエージェントを説明していない）か、要約を打ち直す（まだ説明している）かです。

通常の評価が返した空でない `evolution` は保留中の提案として保たれます。既存の `daily` 動作はホスト側の統合になり、**モデルを呼びません**。同じ構成のもとで確認された予測があり、設定された独立したやり取りの下限（メッセージ数ではなくやり取りの窓で数えます）に達しているときにだけ、独立した進化イベントとして確定します。一日一回の規則、基準値と半減期の上限、`separate_evolution`、差し戻しはそのままです。特性を書けるのは台帳だけで、進化として差し出された特性のスナップショットは、提案された場所で拒まれ、適用されようとする場所でもう一度拒まれます。

## ホストが保証しないこと

- **特性が真実であること。** 保証するのは、引用された材料が実在すること、与えられた種別を名乗るに足ること、互いに離れた時点から来ていること、相手の言葉が逐語で引かれていることです。Kin についてのその文は Kin 自身のものです。
- **権威のラベルが正直であること。** 述語は保存されたものを読むだけです。運用上の証拠は信頼できるホストが取り込む必要があり、時刻の検査は「誰も答えを先に知らなかった」ことを証明できません。
- **経験の数が生きられた経験と一致すること。** 三十分の窓は既存のやり取り窓をそのまま使ったものです。独立した回数を少なく数えることはあっても、多く数えることはありません。それは昇格を遅らせるだけで与えはせず、その間も候補は働いています。
- **述べられた動きが実行されたこと。** `mind_next_moves` は、評価が何を述べ、ホストがその背後に何を見つけたかを記録します。順序も準備状態も変えません。
- **意図が守られたこと。** 意図は言葉づかいに渡される姿勢であって台本ではなく、新しさを失った時点で捨てられます。
- **確認された予測が人格の変更を正しくすること。** それは日次の統合に進む資格を与えるだけで、上限はもとからそこにあります。

## 保存・インターフェース・スイッチ

新しい表は、それを所有するモジュールが必要になった時点で作り、ほかは読みません。古いホストは無視し、差し戻してもそのまま残しておけます。それ以外の新しいデータは既存の `data` JSON に入ります。

| インターフェース | 契約 |
| --- | --- |
| ホスト動作 `traits` / MCP ツール `read_trait_ledger` | 台帳を読む：各特性自身の文、その数と状態、訂正と未決の予測。読み取り専用で、チャットモデルには書き込む手段がありません。 |
| ホスト動作 `trait-revoke` | 次の評価を待てない相手からの訂正。引用された来源が、相手自身の訂正として記録するか、運用者の訂正として記録するかを決めます。 |
| ホスト動作 `traits-migrate` | 古い `state.traits` の記録を台帳へ引き継ぎます。冪等で、ドライランは何も書きません。 |
| ホスト動作 `next-moves` | 読み取り専用：各評価が何をしていると述べ、ホストがその背後に何を導いたか。 |
| ホスト動作 `configure-behavior-models` | このホストが応答に使うモデルを登録します。行動検証の成分のうち、ストアが自力で読めない唯一のものです。登録されるまでは「未登録」で、これは古びているのではなく安定しているということです。 |

スイッチは `memory.DEFAULTS` に登録され、`autonomy_schema.optimized()` で読まれ、`configure-memory` で設定します。六つとも既定で有効です。六つとも無効にした状態が、以前の挙動そのもの、一バイトも違いません。

| スイッチ | 有効になるもの |
| --- | --- |
| `trait_ledger` | `trait_observations`、`trait_decisions`、台帳の表と経路、そして評価の投影とチャット文脈における特性と訂正の項目。 |
| `expression_intent` | `expression_intent`、および姿勢・話題・回避が対応表だけでなく言葉づかいに届くこと。 |
| `next_move_audit` | `next_move` と追記のみの `mind_next_moves`。 |
| `behavior_chain` | `self_hypothesis`、`prediction_outcomes`、互換の刻印、保留中の進化提案、モデルを呼ばない日次統合。無効にすると、一日一回のモデル要求と「同じ agent_version の評定」に戻り、同時にこの段階が終わらせようとした沈黙も戻ります——通常の評価が出した `evolution` は届いた場所で捨てられ、適用も保存も拒否理由の記録もされません。 |
| `wish_version_review` | 判断が以前のエージェント版で下された願いについて、願いと版ごとに `wish-review` を一度だけ出します。未準備のまま誰も二度と見に来ない状態に置き去りにしません。 |
| `rest_review_window` | 次の静かな見直しの上限 `review_rest_max_minutes`＝480 を、律動が休んでいるあいだ、または相手の非通知時間帯のあいだだけ適用します。それ以外では引き続き `review_max_minutes` が決め、どちらの上限なのかは要求に書かれます。 |

既定で無効の `legacy_drive_thresholds` は、固定 75 点の連絡・探索の関門を戻すもので、`semantic_actions` が有効でないあいだだけ働きます。有効か無効かにかかわらず、保存された閾値は数値のままです。

## 何を検査し、何を記録するだけにするか

`tests/test_stage4_contrast.py` は、異なる経験を生きた二つのエンジンに同じ問いを渡し、それぞれが自分の経験でしか説明できないものに依って答えているかを検査します。二つの投影と二つのチャット文脈は経験の違いのとおりに異なり、記録された動きはいずれも、そのエンジンの中で解決できる特性と証拠に依っており、もう一方の経験から借りた根拠は偽造として拒まれ、同じ評価の残りは通常どおり確定します。さらに、六つのスイッチをすべて切った状態で同じ経験を二度たどり——一度は六つのセクションをすべて埋めた回答で、一度はそれらが存在する前の提案で——状態、チャット文脈、保存された行、そしてストアがそもそも持つ表を、一バイト単位で比べます。

`tests/llm/test_personality_contrast.py` は同じ形を実際の評価モデルに対して行います。`llm` の印が付き、通常の実行ではすべて除外され、手で動かします。断言するのはホストが自力で検証できることだけです——確定が通ったこと、根拠と特性参照が答えたエンジンの中でいまも解決できること、解決できない引用として拒まれたものがないこと、そして相手が終わらせた関心を、その経験がいまも持つものとして依りどころにしないこと。二つの答えが違うかどうか、それぞれ何を決めたか、いくらかかったかは `private/llm-receipts/` の下の受領に書き出され、決して断言されません。二つの経験は違う選択をする義務を負わず、同じ選択になった回も失敗ではありません。
