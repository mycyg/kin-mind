# 記憶に基づく自律計画

Kin は評価の中で目標を立て、行動を見直します。ホスト設定で `main_session_review` が有効な場合はメインセッション自身のモデルが評価します。既定では `_kin/assess` で作る一時的な読み取り専用の分岐で行い、`assessment_channel` が `legacy` の場合はセッション内の静かなターンで行います。それ以外は DeepSeek Flash / high が評価します。共有記憶、時刻付きの直近4往復の公開会話、関心、作品、探索結果、共有の受領記録、計画、利用可能な能力がこの評価に入ります。点数は判断材料であり、実行の閾値ではありません。判断がない場合や根拠が古い場合は再評価を待ちます。

感情の点数と短期的な動機の目標は、根拠のある会話、記憶、結果に応じて上下し、設定された半減期で時間とともに変化します。評価は待機・中止を選ぶ時にも `action_decisions.strength`（0–100）を更新できます。強さを省略すると願望の現在の強さを保ち、新しい願望には固定値ではなく現在の動機を使います。点数の高低だけで実行を許可したり取り消したりしません。

既定では、点数は連絡も探索も制限しません。75点の固定閾値は `legacy_drive_thresholds` が有効で `semantic_actions` が無効な場合にだけ働きます。`semantic_actions` を有効にすると、候補選択・取得・送信直前の確認には検証済みの現在の判断が必要です。静穏時間、現在の連絡設定、ユーザーの作業優先、チャネルの権限、根拠と版の検証が決め手です。通常の会話は入力分類の `recall` 判断を再利用し、固定の追加モデル呼び出しは行いません。追加の想起は最大3回・150秒、1回の再順位付けは最大30秒です。任意の処理が失敗した場合は、検証済みのローカル根拠と明示的な不足を返します。

計画には安定した ID、版、目標、動機、根拠、次の評価時刻、手順の依存関係を保存します。担当は `explore`、`create`、`contact`、`owner` です。各手順は目標、完了条件、シンガポール時間の実行窓、前提条件、入力、任意の `owner_request_id` を記録します。長期の計画に7日間の有効期限はありません。実行窓の開始や見逃しは再評価を起こします。再起動後に過去の予定をまとめて送信しません。

再評価はエッジトリガーです。評価時刻の到来、計画の根拠の変更や差し替え、ユーザーの新しいメッセージ、エージェント版の変更、決定どおりに実行できなくなった準備済みの手順——それぞれの理由が一度だけ再評価を起こし、その後 `mind_plan_wakeups` に応答済みとして記録されます。条件が真のまま続いても再び起こしません。複数の理由が同時に成立しても再評価は一度です。計画を読む前に取り下げられた再評価は、引き受けた理由を再び開きます。すでに計画を読んだ再評価の理由は応答済みのままです。`decide` が現在のエージェント版を記録するため、設定の更新はホストの毎分ではなく一度だけ再評価されます。

評価は計画の変更と、`execute`、`wait`、`abandon`、`owner_accepted`、`owner_completed`、`owner_declined` を提案します。ホストは評価のトランザクション内で、添付された根拠一覧と期待する版を確認します。ユーザーの参加には実際のユーザー由来の根拠が必要で、提案・送信した招待・承諾・完了は別々に記録します。モデルが Kin の実行を確定したり、チャネルの受領記録を作り出したりすることはできません。

ホストはモデルに実際に見せた計画ビューも記録します。対象手順の版・状態・判断 ID が一致し、その判断が依拠した根拠——手順の定義、依存する各手順の版・状態・受領記録、計画の目標・動機・根拠の版、ユーザー発話の世代——が変わっていない場合にだけ判断を適用します。この防護を失った判断は例外にせず保留します。`plan-inactive`、`view-missing`、`step-touched`、`basis-changed` のいずれかを確定結果とともに記録し、評価の残りはそのまま確定し、まとめて一度の再評価で問い直します。古い `wait` が新しい `execute` を上書きすることはありません。期待する版が古い場合は、手順と根拠が変わっていないと証明できる時にだけ再基準化します。再基準化された判断は、見ていない版がすでに要求した再評価を先送りできません。記録されたビューがなければ、正確な版だけが根拠です。

保存済みの判断と完全に同じ `wait`——動作、強さ、選択した配信ファイル、方法、前提条件の説明がすべて同じ——は `mind_plan_reviews` に記録し、次の評価時刻だけを進めます。計画の版を消費しないので、他の評価の期待する版を無効にせず、保存済みの判断はそのまま有効です。強さなど内容のある項目が変われば通常の経路で版を上げます。完了した再評価は、判断が保留された計画も含め、見せたすべての計画にエージェント版を登録します。見せられなかった計画には登録せず、その起動理由は開いたままです。未来ではない評価時刻は未指定として扱い、判断は20分後、計画変更は即時の再評価になります。モデルが返した値は監査記録に残ります。

探索エグゼキューターには質問、実際の記憶の抜粋、既知の結論、不足情報、最近の会話を渡します。実行するのは有効なランタイムバンドルの Codex（または明示的に設定した `native_codex_command`）で、専用の探索ゲートウェイ経由で DeepSeek（`exploration_model` は deepseek-flash、`exploration_reasoning` は high）を使います。受領記録は実行器を `codex-cli` と記録し、モデルプロバイダを別に記録します。制作器は `creation_directory` 配下の隔離された作業ディレクトリで同じ Codex を実行し、`creation_model`（既定 `gpt-6-sol`）と `creation_reasoning`（既定 `medium`）を使います。Fast はルーター設定の `workFast` が有効な場合にだけ要求し、ネイティブ実行の受領記録はそのモデルを示す必要があります。制作器は携帯のセッションを再開せず、MCP ツールを読み込まず、ネットワークに出ず、メッセージを送らず、共有状態も書きません。制作の各ステップはホストが責任を持つ1回の実行です（CR5-MM-04）。CLI を起動する前に、その記録がホストの `state/executions/` に書かれ、実行マーク（`KIN_WORKER_MARK`）は名前を指定して CLI、CLI が実行するすべてのシェルコマンド（環境は他の変数を継承しません）、ホストの描画プロセスとそれが起動するブラウザに渡されます。CLI が起動したプロセスがすべて終わってから作業ディレクトリを読み、そのステップのプロセスがすべて終わって初めて、ステップはルーターの実行中集合への登録ごと終わります。正常終了、中断、サービス停止のどれでも同じです。停止時は上限まで待ち、終了を確認できなかった実行は記録を残して次回の起動で片付けます。制作器と探索器は同時に各1個までです。ユーザーの新しいメッセージではどちらも止まりません。ホストは何が動いているかを Kin に伝え、彼女が決めます。ホストがそれらを終了するのは停止時とユーザーの明示的な停止指示の時だけで、ユーザーの作業中は新しい実行を始めないだけです。止まった実行は作業ディレクトリとチェックポイントを保ちます。ファイルの所在、サイズ、ハッシュ、検査可能な内容、別途の DeepSeek による完了評価をホストが確認します。配信には、後の評価の判断が検証済みファイルの `artifact_hashes` を選ぶことが必要で、その後に永続的な送信経路を通ります。不確定な送信は同じ ID で照合します。

有効時、探索器はホスト所有の `kin_ui` を通じて Codex Computer Use を利用できます。探索モデルに渡すのは最新のアクセシビリティ／DOM テキストだけで、スクリーンショットは渡しません。意味上の行動は探索モデルが選びます。ホストが公開するのは固定ツール、当該実行が新規作成したブラウザータブ、設定で正確に許可したネイティブアプリだけです。操作を第二のモデルが審査することはありません。エグゼキューターが操作の種類を宣言し、ホストがユーザーの固定ルールを適用します。送信・公開、支払い、削除、認証情報、システム制御は拒否し、ラベル自体がそれらを示す対象や宣言のない種類は理由を付けて差し戻し、ローカルへの書き込みにはホストが書き込み用に限定した対象が必要です。ホストは実行直前に対象を読み直し、期待した要素とラベルがそのまま表示されている場合にだけ実行します。ネイティブの Computer Use 承認は、許可済みのアプリと操作に対する同じ低リスクの要求だけを受け入れます。設定と限界は[コンピューター探索](computer-exploration.md)を参照してください。

## インターフェースと切り戻し

| インターフェース | 契約 |
| --- | --- |
| `read_autonomous_plans` / `GET /v1/autonomy/plans` | 範囲・ID・状態、ページ、履歴、版、待機理由。 |
| `manage_autonomous_plan` / `POST /v1/autonomy/plans` | 作成・更新・停止・再開・再予定・取消。冪等な命令 ID と根拠が必要。変更は期待する版も指定。 |
| `read_procedure_memory` / `GET /v1/autonomy/procedures` | 方法、根拠、依存の有効性。適用可否は評価が判断。 |

実行の取得・更新・結果・中断・復旧・延期（`plan-claim/renew/result/interrupt/recover/deferral`）はホスト専用で、モデルの完了ツールとしては使えません。復旧はリースの期限が切れた実行だけを取り戻し、残りは `still_leased` として報告します。`liveness_checks` が無効な場合はワーカーの停止が必要です。DB は追加移行とし、モデル処理を書き込みトランザクションの外で行い、確定時に根拠・版・リースを確認します。願望は ID を保って移行し、移行だけで実行を許可しません。

`mind_plan_reviews` は版を作らない再評価——同じ内容の待機の繰り返しと、完了した再評価が登録したエージェント版——を、その理由・判断・提供元の受領記録とともに保存します。`mind_plan_wakeups` は応答済みの起動理由を1件ずつ保存します。どちらも必要時に作成され、他の処理は読まず、切り戻しでもそのまま残せます。

`semantic_actions`、`autonomous_plans`、`creative_execution`、`usage_reinforcement`、`procedure_learning`、`reinforcement_ranking` は独立したフラグで、既定は無効です。ライフサイクルと温度のフラグはそれぞれの意味を保ちます。切り戻しでは対象経路を無効にし、新しい会話、計画履歴、元資料、成果物、受領記録を残します。

`plan_review_record_only` は記憶設定にある独立した最適化スイッチで、既定は有効です。`configure-memory` で明示的に `false` にすると、同じ待機を繰り返すたびに計画の版を一つ消費します。エッジトリガーの起動、記録した計画ビュー、保留された判断はこのスイッチの対象外で、常に有効です。

## 使用頻度と手続き的記憶

明示的な検索、実際の返信での引用、検証済みの作業結果を数えます。チャネルや経路が違っても認証済みの入力 ID で重複排除し、同じ計画の複数手順も1回として扱います。候補への一致、背景注入、保守処理、要約、計画だけでは加熱しません。頻度は半減期30日で減衰し、`log1p` で強度に変換します。事実の確信度を上げたり、訂正済みの事実を復活させたりしません。

頻度の収集と順位への適用は分離しています。`usage_reinforcement` を有効にすると、その重みの版だけの観測が始まります。`reinforcement_ranking` を有効にできるのは、次のすべてを満たす場合だけです。開始から丸7日が経過していること、その版で連続7日の実際の観測日があること、そして `reinforcement_validation` が同じ重みの版、ユーザーの承認、その7日より後の評価時刻、凍結リプレイの出力ファイルとその SHA-256 を示していることです。そのリプレイには48事例以上があり、21件の重要事例がすべて上位8件に入り、44事例以上が上位8件に入っている必要があります。温度評価の期間は流用できません。シャドー指標は順位の違いを記録するだけで、本番の順序は変わりません。

方法には適用条件、手順、ツール・環境の版、成功基準、失敗例、実際の結果の根拠を残します。異なる2つの記録済み事例が隔離リプレイを通過するまでは候補のままです。外部効果には既存の真正な受領記録を使い、試験のために携帯へ再送しません。根拠の訂正、反例、エージェント設定の変更、利用できない環境の版は、現在の実行を止めます。方法は人格や権限を変更できません。

## 性能と検証

キーワード・ベクトル・関係候補を並列で読みます。イベントの要約は同時に最大2件までで、同じイベントについて2件同時には作りません。モデル呼び出しはすべて共有の DB 受付台帳を通り、レーンは呼び出し側が宣言した用途で決まります。バックグラウンドの同時数は 1–8 で設定でき、レーンと各種の待機は後述します。前景のリースがある間、ジョブワーカーは有料モデルを呼ばないジョブだけを取得します。判断を宣言した構造化結果は、描画し終えた要求全体とその判断を鍵として保存し、呼び出し側が自ら検証したと報告してから再利用でき、既定では5分で失効し（呼び出し側は別の有効期間を宣言できます）、依拠した情報源・記録・グラフ対象が変われば直ちに破棄されます。キャッシュの一致は再利用した呼び出しとして記録し、新しい token 消費として数えません。タイムアウトした要求の使用量は不明として残し、遅れて届いた使用量の記録は有効な結果と分けて保存します。

`pytest -q` と `node --test tests/business/*.test.mjs` を実行します。合成の計画事例は長期の目標、時間窓、依存の循環、ユーザーの参加、変更、再起動、並列処理、部分配信、モデル停止を扱います。凍結された48事例の履歴リプレイが、上記の頻度順位の関門です。温キャッシュでのローカル候補の P95 は、ネットワーク・モデルの時間と総 token とは別に測ります。私的会話、リプレイの入力、計画、認証情報は Git に入れません。

設計の参考は [CoALA](https://arxiv.org/abs/2309.02427)、[Mem0](https://arxiv.org/abs/2504.19413)、[Snowflake のコンテキスト層](https://www.snowflake.com/en/blog/agent-context-layer-trustworthy-data-agents/) です。各実験の成果を Kin の実測効果として主張しません。元の根拠、版付きのビュー、元に戻せる状態がシステムの拠り所です。

## 返信、待機、選択したステップの検証

通常の会話や遊びの返信は、整形後に審査モデルを通さず永続的な送信処理へ進みます。共有済みの内容は生成時の参考情報で、配信を拒否しません。自発的な連絡は評価の判断を再利用し、現在の連絡条件を確認し直します。Kin が明示した `choose_reply` の判断（`silent` または `merged`）はそのまま有効です。

そのままでは送れない本文——内部の目印や壊れた封筒を含むもの、またはホストが修復対象とした本文——は取り下げられ、再生成も書き換えもされません。送られなかったという事実だけが本文なしで Kin の次のユーザーターンに伝わり、どう伝えるかは彼女が決めます。ツールや完了済みの作業は繰り返しません。部分送信は受け付けられた内容を保ち、不確定な送信は元の ID を保ちます。

`configure-model-capacity` は DB 全体で共通のバックグラウンド上限（1–8）を設定します。ホストは起動時に設定ファイルの `background_model_limit` も同じ場所へ書き込みます。未設定でも 2 で受け付けますが、`model_capacity_unconfigured` を記録し、状態には `source: "default-unconfigured"` と表示するため、黙って設定済みとして扱うことはありません。受付は呼び出し側が宣言した用途で三つのレーンに分かれます。バックグラウンド、前景優先待ちの対象外でどの呼び出し側も宣言していないユーザー作業用の予約枠、そして常に受け付けて記録だけを行う前景です。詳細は[モデルレーン](kin-mind.md#model-lanes-and-the-lease-interface)を参照してください。受け付けられなかった要求は回数に数えない待機で、独自の回数と再試行間隔を持ち、試行回数を消費しません。評価の中の入れ子の呼び出しは、その評価が受け付けられたリースを再利用します。実際の失敗、部分処理、不明な使用量は記録します。根拠と範囲を指定した受付待ちだけの復旧は、ジョブ ID と履歴を保ち、古い提案を新しい判断として再利用しません。

完了判定は現在の手順の不足 `step_remaining`、後続作業 `downstream`、任意の改善 `advisory` を分けます。`remaining` は現在の手順の不足として読みます。実行器のメモは DeepSeek による完了評価の証拠です。検証が足りない場合、成果物は `phase=needs_verification`、`verification_gaps`、チェックポイント、再開操作を保ちます。評価が返った後、成果物のハッシュと現在の根拠をもう一度確認します。後続の配信やユーザーの応答は別の手順です。

任意の `CreationVerifier` は、ホストが設定した Playwright モジュールとブラウザーを制限付きの子プロセスで使い、静的 HTML を390と1024ピクセル幅で描画します。ページのスクリプト、外部資源、ネットワーク、ダウンロード、Service Worker は無効です。ホストは出典と画像のハッシュ、PNG サイズを再確認します。描画は出力とレイアウトの証拠であって、独立した美的評価の代わりではありません。スクリーンショットや失敗した描画を成功した確認に変えることはできません。任意の描画器は個別に停止でき、ジャーナル、原文、受領記録は残ります。
