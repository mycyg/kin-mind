# 記憶に基づく自律計画

Kin は既存の評価処理で DeepSeek Flash / high を使い、共有記憶、時刻付きの直近4往復の公開会話、関心、作品、探索結果、共有の受領記録、現在の計画から次の行動を判断します。`semantic_actions` が有効な場合、候補選択・取得・送信直前の確認は有効な DS 判断に基づきます。75点の閾値はありません。静穏時間、連絡設定、ユーザーの作業優先、チャネルの権限は維持します。モデル停止や古い根拠は再評価待ちになります。

感情の点数と短期的な動機は、根拠のある新しい会話、記憶、結果に応じて上下し、設定された半減期で時間とともに変化します。DS は待機・中止を選ぶ時にも `action_decisions.strength`（0–100）を更新できます。省略時は既存の願望の強さを保持し、新しい願望には現在の動機を使います。点数だけで実行を許可したり取り消したりしません。

計画には安定した ID、版、目標、動機、根拠、次の評価時刻を保存します。各手順には担当者、完了条件、依存関係、前提条件、シンガポール時間の実行窓があります。担当は探索・制作・連絡・ユーザーです。長期目標に7日間の有効期限はありません。期限到来、実行窓の開始・終了、新しい関連会話、根拠の変更は再評価を起こします。再起動後に過去の予定をまとめて送信しません。

再評価はエッジトリガーです。評価時刻の到来、計画の根拠の変更や差し替え、ユーザーの新しいメッセージ、エージェント版の変更、決定どおりに実行できなくなった準備済みの手順——それぞれの理由が一度だけ再評価を起こし、その後 `mind_plan_wakeups` に応答済みとして記録されます。条件が真のまま続いても再び起こしません。複数の理由が同時に成立しても再評価は一度です。計画を読む前に取り下げられた再評価は、引き受けた理由を再び開きます。すでに計画を読んだ再評価の理由は応答済みのままです。`decide` が現在のエージェント版を記録するため、設定の更新はホストの毎分ではなく一度だけ再評価されます。

DS は実行・待機・中止、ユーザーの承諾・完了・辞退を提案します。ホストがトランザクション内で根拠、版、リースを検証します。`owner_request_id` で依頼を関連付け、提案・送信・承諾・実際の完了を別々に記録します。モデルの完了宣言だけでは実行や配信を確定できません。

ホストはモデルに実際に見せた計画ビューも記録します。対象手順の版・状態・判断 ID が一致し、その判断が依拠した根拠——手順の定義、依存する各手順の版・状態・受領記録、計画の目標・動機・根拠の版、ユーザー発話の世代——が変わっていない場合にだけ判断を適用します。この防護を失った判断は例外にせず保留します。`plan-inactive`、`view-missing`、`step-touched`、`basis-changed` のいずれかを確定結果とともに記録し、評価の残りはそのまま確定し、まとめて一度の再評価で問い直します。古い `wait` が新しい `execute` を上書きすることはありません。期待する版が古い場合は、手順と根拠が変わっていないと証明できる時にだけ再基準化します。再基準化された判断は、見ていない版がすでに要求した再評価を先送りできません。記録されたビューがなければ、従来どおり正確な版だけが根拠です。

保存済みの判断と完全に同じ `wait`——動作、強さ、選択した配信ファイル、方法、前提条件の説明がすべて同じ——は `mind_plan_reviews` に記録し、次の評価時刻だけを進めます。計画の版を消費しないので、他の評価の期待する版を無効にせず、保存済みの判断はそのまま有効です。強さなど内容のある項目が変われば従来どおり版を上げます。完了した再評価は、判断が保留された計画も含め、見せたすべての計画にエージェント版を登録します。見せられなかった計画には登録せず、その起動理由は開いたままです。未来ではない評価時刻は未指定として扱い、判断は20分後、計画変更は即時の再評価になります。モデルが返した値は監査記録に残ります。

Kimi には質問、実際の記憶の抜粋、既知の結論、不足情報、最近の会話を渡します。独立した制作実行器は設定済みの作業モデルと隔離ディレクトリを使います。携帯の共有セッションを再開せず、その MCP や送信権限も使いません。初期状態では探索器と制作器を各1個とし、ユーザーの作業が来たらチェックポイントを保存して譲ります。ファイルの所在、サイズ、ハッシュ、検査可能な内容、DS の完了評価をホストが確認します。後続の連絡判断が検証済みファイルの `artifact_hashes` を選び、既存の永続送信経路で配信します。不確定な送信は同じ ID の受領記録で照合します。

## インターフェースと切り戻し

| インターフェース | 契約 |
| --- | --- |
| `read_autonomous_plans` / `GET /v1/autonomy/plans` | 範囲・ID・状態、ページ、履歴、版、待機理由。 |
| `manage_autonomous_plan` / `POST /v1/autonomy/plans` | 作成・更新・停止・再開・再予定・取消。冪等な命令 ID と根拠が必要。変更は期待する版も指定。 |
| `read_procedure_memory` / `GET /v1/autonomy/procedures` | 方法、根拠、依存の有効性。適用可否は DS が判断。 |

実行結果と復旧はホスト専用です。DB は追加移行とし、モデル処理を書き込みトランザクションの外で行い、確定時に根拠・版・リースを確認します。既存の願望は ID を保って移行し、移行だけで実行を許可しません。

`mind_plan_reviews` は版を作らない再評価——同じ内容の待機の繰り返しと、完了した再評価が登録したエージェント版——を、その理由・判断・提供元の受領記録とともに保存します。`mind_plan_wakeups` は応答済みの起動理由を1件ずつ保存します。どちらも必要時に作成され、他の処理は読まないため、古いホストは無視し、切り戻しでもそのまま残せます。

`semantic_actions`、`autonomous_plans`、`creative_execution`、`usage_reinforcement`、`procedure_learning`、`reinforcement_ranking` は独立したフラグで、既定は無効です。切り戻しでは対象経路を無効にし、新しい会話、計画履歴、元資料、成果物、受領記録を残します。

`plan_review_record_only` は記憶設定にある独立した最適化スイッチで、既定は有効です。`configure-memory` で明示的に `false` にした時だけ、同じ待機の繰り返しごとに計画の版を上げる従来の動作に戻ります。エッジトリガーの起動、記録した計画ビュー、保留された判断はこのスイッチの対象外で、常に有効です。

## 使用頻度と手続き的記憶

明示的な検索、実際の返信での引用、検証済みの作業結果を数えます。同じ入力のチャネル間再生は重複排除し、同じ計画の複数手順も1回として扱います。候補への一致、背景注入、走査、要約、計画だけでは加熱しません。頻度は半減期30日で減衰し、`log1p` で強度に変換します。事実の確信度を上げたり、訂正済みの事実を復活させたりしません。

頻度の収集と順位への適用は分離します。新しい重みの版で実際に連続7日を観測し、7日間が経過し、同じ版の評価とユーザーの判断を得てから順位適用を有効にします。以前の温度評価の日数は流用できません。

方法には適用条件、手順、ツール・環境の版、成功基準、失敗例、実際の結果の根拠を残します。異なる2事例の隔離リプレイを通過するまでは候補です。外部効果は既存の真正な受領記録を使い、試験のために携帯へ再送しません。訂正、反例、設定や依存の変更は再評価の対象です。方法は人格や権限を変更できません。

## 性能と検証

キーワード・ベクトル・関係候補を並列で読み、異なるイベントの要約も並列化します。同じイベントには1つの有効な生成処理だけを許します。モデル呼び出しはすべて共有の DB 受付台帳を通り、レーンは呼び出し側が宣言した用途で決まります。バックグラウンドの同時数は 1–8 で設定でき、レーンと各種の待機は後述します。構造化判断は、描画し終えた要求全体とそれが答える判断を鍵として保存し、呼び出し側が自ら検証したと報告してから再利用でき、最長5分で失効し、依拠した情報源・記録・グラフ対象が変われば直ちに破棄されます。キャッシュ、実際の token、未知の使用量を区別し、再利用は新しい token 消費として数えません。タイムアウトを無料とは扱いません。

通常の会話は既存の入力分類から想起モードを受け取り、固定の追加モデル呼び出しは行いません。深い想起は最大3回・150秒、1回の再順位付けは最大30秒です。失敗時は検証済みのローカル根拠と不足情報を返します。

`pytest -q` と `node --test adapters/*.test.mjs` を実行します。私有の凍結48事例は重要事例21/21、上位8件の的中44/48以上が基準です。計画、再起動、並列取得、部分配信、モデル停止も検証します。約1万件の温キャッシュによるローカル候補の P95 は500ミリ秒を目標とし、モデル・ネットワークの時間と総 token は別に報告します。私的会話、計画、評価入力、認証情報は公開しません。

設計の参考は [CoALA](https://arxiv.org/abs/2309.02427)、[Mem0](https://arxiv.org/abs/2504.19413)、[Snowflake のコンテキスト層](https://www.snowflake.com/en/blog/agent-context-layer-trustworthy-data-agents/) です。各実験の成果を Kin の実測効果として主張しません。

## 返信、待機、選択したステップの検証

`share-preflight-group` は対応するユーザー入力、公開会話、出典、送信履歴とともに返信全体を一度に DS high へ渡します。許可・修正・保留と各吹き出しの元 ID を返します。保留は送信完了ではありません。沈黙や入力統合は実際の `choose_reply` 記録だけで確定します。送信前に本文を固定し、再起動後も同じ ID の受領証を照合します。モデル切替通知や古い返信は新しい入力を完了させません。

`configure-model-capacity` は全プロセス共通のバックグラウンド上限（1–8）を設定します。ホストは起動時に設定ファイルの `background_model_limit` も同じ場所へ書き込みます。未設定でも 2 で受け付けますが、`model_capacity_unconfigured` を記録し、状態には `source: "default-unconfigured"` と表示するため、黙って既定値に戻ることはありません。受付は呼び出し側が宣言した用途で三つのレーンに分かれます。バックグラウンド、前景優先待ちの対象外となるユーザー作業用の予約枠、そして常に受け付けて記録だけを行う前景です。詳細は[モデルレーン](kin-mind.md#model-lanes-and-the-lease-interface)を参照してください。要求前の空き待ちと前景優先待ちは失敗回数に含めず、独立した待機回数と再試行間隔を記録します。実際の失敗、部分処理、不明な使用量は保持します。

完了判定は現在の不足 `step_remaining`、後続作業 `downstream`、任意の改善 `advisory` を分けます。実行器の未完了メモは DS が分類する証拠です。検証待ちでは成果物、作業ディレクトリ、具体的な不足と再開操作を保存します。後続の配信やユーザー応答を現在の制作条件に追加しません。

任意の静的 HTML 検証器はスクリプト、外部ネットワーク、外部ローカル資源、ダウンロードを無効にし、スマートフォンとデスクトップ幅で描画します。ホストは出典と画像のハッシュ、PNG サイズを再確認します。描画記録は独立した美的評価の代わりではありません。全体返信審査と検証器は個別に停止でき、原文、履歴、受領証は残ります。
