# Memory-backed autonomous planning

Kin forms goals and reviews actions in the assessment. With `main_session_review` set in the host configuration, the main session's own model makes it — in an ephemeral read-only fork taken through `_kin/assess`, or as a quiet turn in the session when `assessment_channel` is `legacy`; otherwise DeepSeek Flash / high does. Memories, four recent timestamped public turns, unresolved matters, artifacts, exploration outcomes, sharing receipts, plans and available capabilities enter that appraisal. A score is context, never an execution threshold. A missing or stale decision waits for review.

Affect scores and short-term motivation targets rise or fall with sourced conversation, memory and outcomes, and evolve over time using their configured half-lives. The assessment may update `action_decisions.strength` (0–100) even when waiting or abandoning. An omitted strength keeps the wish's current strength; a new wish uses its current motivation instead of a fixed default. Neither a high nor a low score grants or revokes execution by itself.

## Decisions, plans and execution

By default scores gate neither contact nor exploration: the fixed 75-point gates apply only with `legacy_drive_thresholds` on and `semantic_actions` off. With `semantic_actions`, candidate selection, claim and pre-send validation require a current verified decision. Quiet hours, current contact preferences, user work priority, channel permissions and source/version validation stay authoritative. Normal chat reuses the input classifier's `recall` decision; it does not add a fixed model call. Optional memory expansion is capped at three rounds and 150 seconds, with each reranker capped at 30 seconds. Optional failures return verified local evidence and explicit gaps.

Plans have stable IDs, revisions, goal, motivation, source references, next review time and a dependency graph of steps. Actors are `explore`, `create`, `contact` and `owner`. Each step records its goal, completion criterion, Singapore time window, prerequisites, inputs and optional `owner_request_id`. Long-term plans have no seven-day expiration. A time window opening or being missed triggers another review. Restart never authorizes accumulated catch-up messages.

Reviews are edge-triggered. Each distinct reason — a due review time, a changed or superseded plan source, a new owner message, a new agent version, or a ready step that can no longer run as decided — wakes one review and is then recorded as answered in `mind_plan_wakeups`. A condition that merely stays true wakes nothing more, and separate reasons that happen to coincide still cost one review. A review set aside before it read the plan reopens the reasons it had taken; one that already read the plan keeps them answered. `decide` stamps the current agent version, so a configuration upgrade is reviewed once instead of on every host minute.

The assessment proposes plan changes and `execute`, `wait`, `abandon`, `owner_accepted`, `owner_completed` or `owner_declined`. The host checks the supplied source manifest and expected revision in the appraisal transaction. Owner participation requires an actual owner source. A proposal, delivered invitation, acceptance and completion stay distinct. A model cannot settle Kin execution or manufacture a channel receipt.

The host also records the plan view an evaluation was actually shown, and applies each decision only while the target step's revision, state and decision ID still match it, and while the basis that decision rested on is unchanged: the step definition, the revision, state and receipts of every step it depends on, the plan's goal, motivation and evidence revisions, and the owner epoch. A decision that lost that fence is held, never raised — `plan-inactive`, `view-missing`, `step-touched` or `basis-changed` is recorded with the committed result, the rest of the evaluation still commits, and one coalesced review asks again. So a stale `wait` cannot overwrite a newer `execute`. A stale expected revision is rebased only when the step and its basis are provably unchanged, and a rebased decision cannot postpone a review that the revision it never saw had asked for. Without a recorded view an exact revision is the only proof.

A `wait` that repeats the stored decision unchanged — same action, strength, selected delivery artifacts, procedures and accounted preconditions — is written to `mind_plan_reviews` and advances only the next review time. No plan revision is spent, so no other evaluation's expected revision is invalidated and the stored decision stays current; any changed business field such as strength takes the normal path and bumps the revision. A completed review registers the agent version for every plan it was shown, including plans whose decisions were held; a plan it could not show registers nothing and keeps its wake-up reasons open. A review time that is not in the future is treated as omitted: a decision falls back to twenty minutes ahead and a plan change asks for a review at once, while the model's own value stays in the audit row.

The exploration executor receives a question plus actual memory excerpts, known findings, gaps and recent dialogue. It runs the Codex of the active runtime bundle (or an explicitly configured `native_codex_command`) against DeepSeek — `exploration_model` deepseek-flash at `exploration_reasoning` high — through the dedicated exploration gateway; receipts label the executor `codex-cli` and record the model provider separately. The creator runs the same Codex in an isolated workspace under `creation_directory`, with `creation_model` (default `gpt-6-sol`) at `creation_reasoning` (default `medium`), and asks for Fast only when the router configuration's `workFast` is on. Its native execution receipt must name that model. It does not resume the phone session, load MCP tools, reach the network, send messages or write shared state. Each creation step is one execution the host owns (CR5-MM-04): its record is on disk under the host's `state/executions/` before the CLI starts, and its mark (`KIN_WORKER_MARK`) is handed by name to the CLI, to every shell command it runs (whose environment inherits nothing else) and to the host's render worker and the browser that starts; the workspace is read only once nothing the CLI started is still running, and the step, with its place in the router's in-flight set, ends only once nothing of it is left -- after a normal end, an interruption or a shutdown. A shutdown waits for that up to its limit and leaves the record of what it could not see end to the next start. One creator and one explorer run at a time. A new owner message stops neither: Kin is told what is running and decides, the host ends them only at shutdown or on the owner's literal stop, and busy owner work only keeps a new run from starting; a stopped run keeps its workspace and checkpoint. The host verifies artifact containment, size, hashes, inspectable content and a separate DeepSeek completion review. Delivery requires a later assessment decision selecting verified artifact hashes, followed by the durable channel outbox. An uncertain send is reconciled with the same ID.

When enabled, the explorer can use the host-owned `kin_ui` interface backed by
Codex Computer Use. The exploration model receives fresh accessibility/DOM text,
never a screenshot, and chooses the semantic action. The host exposes only fixed
tools, run-owned browser tabs and exact configured native apps. No second model
reviews an interaction: the executor declares its category and the host applies
the owner's hard rules. Sending or publishing, payment, deletion, credentials and
system control are refused; a target whose label names one of them, or an
undeclared category, is handed back with its reason; a local write needs a target
the host scoped for writing. The target is read fresh right before the action
and must still show the expected element and label. Native Computer Use approval
is accepted only for the same low-risk request on an allowed app and action. See
[computer exploration](computer-exploration.md) for configuration and limits.

## Storage, APIs and feature flags

Additive SQLite tables store plans/history, fenced runs, the shared model-lease ledger, procedural memory/history/trials, effective-use events and independent strength observations. `mind_plan_reviews` keeps reviews that are not revisions — a repeated unchanged wait, and the agent version a completed review registered — with the reason, decision and provider receipt of each; `mind_plan_wakeups` keeps one row per answered wake-up reason. Both are created on demand and read by nothing else, and a rollback leaves them in place. Model calls run outside write transactions; source, revision and lease checks fence late results. Desires migrate by stable identity without being granted execution.

| Interface | Contract |
| --- | --- |
| `read_autonomous_plans` / `GET /v1/autonomy/plans` | Scope, optional ID/status, pagination and history; returns revisions and waiting reasons. |
| `manage_autonomous_plan` / `POST /v1/autonomy/plans` | Idempotent `command_id`; create/update/pause/resume/reschedule/cancel. Changes require expected revision and sourced reason. |
| `read_procedure_memory` / `GET /v1/autonomy/procedures` | Sourced method candidates, validity and dependency review state. The assessment judges applicability. |
| Private `plan-claim/renew/result/interrupt/recover/deferral` | Host executor receipts; unavailable as model completion tools. Recovery takes back only executions whose lease has expired and reports the rest under `still_leased`; without `liveness_checks` it requires stopped workers. |

Independent flags: `semantic_actions`, `autonomous_plans`, `creative_execution`, `usage_reinforcement`, `procedure_learning`, `reinforcement_ranking`. They default off. Lifecycle and temperature flags keep their own meanings. Turn off the affected path to roll back; retain new chats, plan history, source records, files and delivery receipts.

`plan_review_record_only` is a separate optimization switch in the memory configuration and defaults on; an explicit `false`, set through `configure-memory`, makes a repeated unchanged wait spend a plan revision. Edge-triggered wake-ups, the recorded plan view and held decisions are not covered by it and stay in force either way.

## Effective use and learned methods

Effective use is counted for explicit queries, actual reply references and verified task results. Deduplication spans channels and origins by authenticated input ID; all steps of a plan share one use key. Candidate hits, automatic background injection, maintenance, summaries and planning do not heat memory. Decayed frequency has a 30-day half-life and `log1p` strength. It does not alter confidence or revive corrected facts.

Frequency collection and ranking are separate. Turning `usage_reinforcement` on starts the weight version's own observation, and `reinforcement_ranking` is refused until all of this holds: seven full days since that start, seven consecutive observation days of that version, and a `reinforcement_validation` that names the same weight version, carries the owner's approval, was evaluated after those seven days and points to the frozen replay's output file with its SHA-256. That replay must show at least 48 cases, all 21 critical cases within the first eight results and at least 44 cases within the first eight. A temperature trial does not count. Shadow metrics record proposed ranking differences while production order stays unchanged.

A procedure preserves applicability, steps, tool/environment versions, success criteria, counterexamples and actual outcome sources. It stays a candidate until two distinct recorded cases pass isolated replay. External effects use genuine recorded receipts; tests never resend phone content. Source changes, counterexamples, agent configuration changes or unavailable environment versions prevent current execution. Methods cannot edit persona or permissions.

## Concurrency, accounting and validation

Keyword, vector and graph candidates are read concurrently. At most two event digests run at once, never two for the same event. One shared database ledger admits every model call on the lane its caller declares, with background concurrency a configurable 1–8; the lanes and their waits are below. While a foreground lease is held, the job worker claims only jobs that call no paid model. A structured decision that declares its judgment is cached under the digest of the fully rendered request together with that judgment, becomes servable only once the caller reports that it validated the result, lives five minutes unless the caller declares another validity, and is dropped as soon as a source, record or graph object it rested on changes. A cache hit is recorded as a reused call and claims no token consumption. Timed-out requests keep unknown usage; late usage receipts stay separate from effective results.

Run `pytest -q` and `node --test tests/business/*.test.mjs`. Synthetic planning cases cover long horizons, time windows, dependency cycles, owner participation, changes, restart, concurrency, partial delivery and unavailable models. The frozen 48-case history replay is the gate for frequency ranking described above. Measure warm local candidate P95 separately from network/model latency and total token cost. Keep private chats, replay inputs, credentials and plans outside Git.

The engineering references inform design, not a claim of measured Kin savings: [CoALA](https://arxiv.org/abs/2309.02427), [Mem0](https://arxiv.org/abs/2504.19413), and [Snowflake's agent context layer](https://www.snowflake.com/en/blog/agent-context-layer-trustworthy-data-agents/). Original evidence, versioned views and reversible state are the system's authority.

## Reply review, admission waits and step verification

Ordinary chat and entertainment replies go through formatting and the durable sender with no review model. Earlier shares inform generation rather than vetoing delivery. Proactive contact reuses the assessment's decision and rechecks current contact conditions. Kin's explicit `choose_reply` decisions — `silent` or `merged` — stand.

A body that cannot go out as written — carrying a private marker or a broken envelope, or flagged for repair — is withdrawn, never regenerated or rewritten. Kin's next owner turn is told that it went unsent, without its words, and she decides what to say. Tools and completed work are not repeated. Partial sends keep accepted content; uncertain sends keep their original IDs.

`configure-model-capacity` sets one database-wide background limit; the host's `background_model_limit` is written to the same place at start-up, and a missing limit is reported (`model_capacity_unconfigured`, `source: "default-unconfigured"`) rather than silently assumed, while admission uses 2. Admission has three lanes chosen from the caller's declared purpose: background, a reserved user-work slot that does not yield to foreground sessions and that no caller declares, and foreground, which is always admitted and only recorded; see [model lanes](kin-mind.md#model-lanes-and-the-lease-interface). A request no lane admitted is an uncharged wait with its own counter and backoff and consumes no attempt. An appraisal's nested calls reuse its admitted lease. Actual failures, partial work and uncertain usage are recorded. Sourced, bounded admission-only recovery preserves job IDs/history and never reuses an old proposal as a new decision.

Completion review separates `step_remaining`, `downstream` and `advisory`. A `remaining` list is read as a current-step gap; executor notes are evidence for the DeepSeek completion review. Produced artifacts keep `phase=needs_verification`, `verification_gaps`, a checkpoint and resume action when checks are missing. Artifact hashes and current evidence are checked again after the review returns. Later delivery and owner responses are separate steps.

The optional `CreationVerifier` uses a host-configured Playwright module and browser in a bounded child process. Static HTML is rendered at 390 and 1024 pixels with page scripts, external resources, network, downloads and service workers disabled. Source/image hashes and PNG dimensions are verified again by the result host. Rendering is evidence of output and layout, not an independent aesthetic review. No screenshot or failed rendering can be converted into a successful check. The optional renderer can be disabled independently; keep journals, sources and receipts.
