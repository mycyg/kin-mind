# 手机伴侣指令与运行时升级

私有宿主通过 `model_instructions_file` 加载伴侣基础指令，并从已确认的人格与说话
风格生成 `developer_instructions`。具体人格正文和共同经历留在私有宿主，公开库
保存通用接入机制与合成测试。

Kin 可以有不同意见和情绪，也可以结合实际状态与原因决定接受、延期、减少投入或
拒绝工作，不使用固定情绪分数门槛。拒绝沿已有任务和投递记录结清，未做的事不会
登记为完成。

## 指令怎样进入原生会话

手机的 app-server 运行在 Kin 自己的 Codex 运行目录 `state/codex-home` 上，部署
通过 `CODEX_HOME` 指向它，不读取桌面的运行目录。每次启动前，宿主按非机密模板、
心智配置和聊天权限重新生成其中的 `config.toml`：只有记忆工具服务和可选的
computer use，关闭 apps、plugins、多智能体、hooks、原生 memories 和技能说明层。
`auth.json` 是指向桌面登录的链接，内容从不读取。运行目录里出现 `AGENTS.md` 时
启动直接停止，不会被注入；`kin-check` 报出配置漂移、认证链接变化、运行目录中的
`AGENTS.md` 或 `hooks.json`，以及会话工作目录里的 `.codex` 项目层。

ACP 启动配置再加入伴侣基础指令、开发者指令、候选包冻结的模型目录、
`include_collaboration_mode_instructions=false`、`project_doc_max_bytes=0` 和
`compact_prompt`；候选包的固定启动器重复影响每个请求的开关。冻结的模型目录使用
标准 Responses（`use_responses_lite=false`），并去掉会附加多智能体层的版本字段。
项目规则和操作说明按需读取；原生工具和实际权限仍由 Codex 提供。

`compact_prompt` 保留当前话题、关系语境、情绪、明确更正和约定，Kin 自己的兴趣与
决定，用户的目标与已获授权范围，每个未完成任务的编号、inputVersion、进度和下一步，
以及哪些回复已经发出、各有什么回执。原生兼容证明在本地回环提供方上确认压缩请求带有
这段提示；提供方自己执行的压缩不在证明范围内。会话管理在每次压缩完成后、下一次派发
前恢复带来源的检查点（见[手机会话](mobile-sessions.md)）。

模型、思考强度与 Fast 偏好保持原选择；实际服务档位以提供方或原生回执为准。

## 候选验证与激活

公开的 `adapters/mobile-runtime-bundle.mjs` 提供按版本的准备、验证、激活、状态读取、
解析与回退。运行包保存 Codex 程序、ACP 包及其白名单依赖闭包和宿主自有的 ACP 入口，
每个文件的哈希记在清单里，清单不记录绝对来源路径。自有入口由未经修改的第三方入口经
字符串补丁生成，每个锚点必须恰好匹配一次，上游变化会让准备停下等待审查。它提供会话
管理使用的 `_kin/*` 扩展（运行状态、最后回复、有时限的压缩及可用 `checkOnly` 再读的
回执、检查点注入、会话退役、输入状态和只读评估分叉），并在每个回合传入伴侣开发者
指令。安装公共库本身不会接管手机会话，也不会安装 Codex 版本。

验证只运行仓库自带的证明程序，不接受调用方提供的证据。它以手机的形态（候选包的
Codex 运行目录设置，不含工具服务和凭据）启动运行包里的 ACP 和启动器，连接本地合成
提供方，记录原生 RPC 与 HTTP，并检查指令加载、新建与恢复会话、维护候选、带候选
`compact_prompt` 的压缩、重启、模型／思考强度／Fast 偏好切换，以及一次本地工具调用。
请求里只能有伴侣基础指令、开发者指令以及权限和模型切换说明，不能出现模型目录模板或
`AGENTS.md`。回执写明自己是协议层证明，列出不覆盖的部分（真实提供方请求、提供方侧
压缩、工具服务、凭据和宿主启动脚本），并记录当前 Codex 是否在 ACP 包声明的版本范围内。

同一份原子激活索引保存当前和上一版；重复激活当前版本不产生新切换。回退回到上一个已
验证的运行包；如果它的 Codex 比已经写过当前线程的版本旧，除非给出
`--allow-downgrade`，否则拒绝。核验不通过的当前运行包不会被启动，也不会退回全局
CLI 或改动桌面安装。

## 每日升级

私有宿主的每日检查（launchd 任务）先运行 `kin-check`，只升级检查通过的安装。它把
本机已安装的稳定版 Codex 和候选输入的指纹（程序、当前运行包的 ACP、已确认的人格、
影响运行包／指令／证明的源文件和冻结的模型目录）与当前候选比较，不同就准备并证明新
候选。被拒绝的候选在输入变化或明确要求重试之前不会重新测试；失败的尝试改名搁置，不会
删除。准备过程不移动激活指针，也不重启任何服务。

已验证的候选只经 `kin-deploy runtime-upgrade` 激活：两个通道都 15 分钟没有用户输入
后，冻结派发，最多等待 10 分钟让在途事项结清，停止宿主，应用候选的配置增量，移动激活
指针，重新生成 Kin 的 Codex 运行目录，重启并核验宿主（`kin-check`、一次只读工具调用、
没有在途输入），然后解冻。从停止宿主起任何一步失败，都会恢复配置和上一版指针、重启
宿主，并给用户发系统通知。会话绑定、历史、任务和回执都不移动。

服务启动时，宿主用当前运行包里的 Codex、在 Kin 的运行目录上刷新观察到的提供方模型
目录；结果作为下一个候选的输入，实际生效的只有已证明候选的冻结目录。创作和探索使用
当前运行包里的 Codex（或明确配置的 `native_codex_command`），存在 Kin 的运行目录时
就使用它，并保留各自的契约。只有未安装运行包时才使用配置的 `creation_command` 或
`exploration_command`，回执把来源记为 `legacy-command`；运行包无法读取时它们等待，
不改用桌面 CLI。

## 验证与记录

配置声明、文件就绪、原生加载、实际请求是分别记录的事实。`instructionSources` 可能
为空而请求正文正确；原生加载会去掉基础文件首尾的空白。证明核对捕获到的请求，不编造
元数据；标题生成请求与它所服务的回合分开计数。内容摘要保护发布文件的字节，不证明语义
判断或投递回执。

在生产环境中，绑定当前会话且已完成的网关请求，或主线程记录的开发者消息及其后的一个
回合，才核验正在运行的指令。恢复的线程保留它记录过的开发者消息，直到一次压缩或新线程
重建上下文；在此之前宿主报告 `developer-differs`。人格正本未通过核验、与批准记录不符，
或拼出的指令与固定的那一份不同时，手机使用当前候选冻结的上一版已批准指令启动，并报告
差异；新人格只经新的候选生效。
