# 特征账本、表达意图与行为验证

个性曾经是一个没人写过的字段：`traits` 一直是空的，没有任何调用方创建过声明或预测，普通评估给出的人格提案被静默丢弃。现在，本来就会发生的那次评估多了六个可选段落，每个段落各有开关，并共用一条规则：**宿主只核对被引用的材料是否真实、是否配得上它被声明的类别、是否来自互相分开的时间；它不评判那句话本身。** 关于 Kin 是什么样的人，那句话是 Kin 自己的；宿主只为它背后的依据担保。

每个新段落默认为空、可选。开关关闭时，它的属性、类型定义与提示词段落一并从请求里去掉；即使模型仍然返回，也在任何人读到之前被置空；落库的提案省略它，旧版本照样能读那一行。被拒绝的段落只影响自己：同一次评估的情绪、愿望与计划决策照常提交，拒绝原因记入 `mind_section_refusals`，而且**不会因此再排一次付费的模型调用**——下一次评估通过对应的投影看到这条拒绝。历史通道、追问、连续性引导与会话维护都不携带这些段落。评估进行中用户又说了话时，只有 `trait_observations` 照常提交，决定与意图留到下一轮。

## 特征账本

`trait_ledger` 启用 `trait_observations`（每次评估最多 4 条）与 `trait_decisions`（最多 2 条），以及 `mind_traits`、`mind_trait_history`、`mind_trait_observations`、`mind_trait_dependents` 四张表。

**观察**是某一段经历里，支持或反对某一条特征的一份证据。该表只追加，身份取决于证据本身而不是复述它的次数，所以同一条特征在同一段经历、同一极性下只记一条观察：一个互动窗口里的十条消息是发生过一次，不是十次。**经历**由宿主判定，按优先次序取执行 id、把间隔三十分钟以内的用户消息合并成的互动窗口、或者这句话的根来源；同一句话被两个命名空间收录，仍然是一个根、一段经历。调用方可以合并经历，永远不能拆分宿主的经历。

什么材料能作什么证据，由证据类别决定，而不是由谁写的文本决定。`owner_statement` 是用户本人说的话：explicit 权威、user 角色、message 事件、用户命名空间、非 generated，且不是配置或自我认知记录——配置与人设来源同样带 explicit 权威，在这里会被拒。`verified_behavior` 是 Kin 真的做过的事，通过 `result_ids` 引用宿主自己解析出的执行回执：已完成且已核验的计划运行、已核验的任务结果、带平台消息号的已接收交付，或已完成的探索。探索自己的报告属于 `self_statement`，因为那是 Kin 写的；它的回执才是行为。`mind-internal-event` 来源在任何类别里都不算证据。被引用的证据编号必须落在本次评估的可用集合内。

特征从被提出的那一刻起就生效。`establish` 表示这段共同经历确实带着它；当 basis 是 `inference` 时，这需要至少两段互不相同的经历、至少一条不是 Kin 自述的支持观察，并在陈述里点名至少两条经历不同的观察、说明它们为何不同。不满足就以 `trait-single-episode` 拒绝，候选继续生效。`owner_instruction` 与 `owner_correction` 要求每一条被引用的材料都通过用户原话谓词，且 `quote` 必须是所引记录里的逐字子串；撤销所依据的证据不能早于这条特征。被撤销的特征留下墓碑——原因、终结它的来源，以及照样可读的历史——同一个键要重新提出，需要比墓碑更新的用户原话。支持度按既有的三十天半衰期衰减：支持已经衰减殆尽的特征在任何写入之前就读作淡出，账本的下一次写入把它记下来。观察下面的来源发生变动时，特征转为 `needs_review`；待复核的特征既不算成立，也不会作为可继续建构的候选被提供。

哪些类别可以生长，完全由已批准的人设契约决定，别处说了不算；中文类别名会被映射成它指向的那一个键。评估模型看到最多 12 条特征，成立与候选分开列出，给的是计数而不是证据原文——每个类别的观察数与经历数、非自述支持、反例、跨越的天数、是否全在一个窗口内——再加上最多 6 条更正及终结它们的来源，以及这份投影自己那部分的最近一次拒绝。聊天模型看到同一份账本，作为 `self-traits` 与 `trait-corrections` 两个独立条目，basis 都是 `self_knowledge`，因为这些都不是用户在说话。开关关闭时两者一并消失，上下文与从前一致。

## 表达意图

`expression_intent` 让同一次评估说出接下来几轮想怎么在场：一句姿态、最多两个还想接着聊的话题、最多两件先不碰的事，以及这份姿态大概还算数多久（10 到 720 分钟）。在此之前，聊天模型只能从一张查表里得知 Kin 的状态——按数值落点选出的固定句子，真正被判断到的东西一点也进不到措辞里。

宿主只核对材料是否真实：本次评估收到的证据、账本此刻仍持有且版本与展示时一致的特征、本范围内现有的心事。解析不了的引用只拒绝意图本身，原因是 `trait-unknown`、`intent-concern-unknown` 或 `intent-evidence-unknown`。姿态永远不会被照抄，也不是台词：它说的是怎么在场，措辞仍由人设决定。被点名的心事会排在这轮继续跟进的前面；没写编号的话题也能找到与它重叠的那条心事。

意图只在新鲜时使用，过期之后绝不。它在下列情况结束：自己的分钟数用完、依据的证据变动、引用的特征被改写或撤销、连续性未激活、人设改变。**新的用户消息刻意不在其中**：对一条消息的回复写在对这条消息的评估之前，因此一份一到消息就作废的意图根本没有机会被用上。任何一种不成立的情况下，措辞都逐字节回落到那张查表。

## 一次评估对自己动作的交代

`next_move_audit` 让一次评估说出它正在做什么、这件事依据什么，并记入只追加的 `mind_next_moves`。它只是审计，别无其他：**它不排序，也不让任何东西就绪。** 每个愿望、每个计划步骤的选取方式，与从未记录过任何动作时完全一样；读取愿望或调度行动的代码，没有一处知道这张表存在。

模型只声明三个词之一——`reply`、`quiet`、`rest`——更完整的那个词由宿主给出。宿主读的是这次评估真正提交了什么，而不是它提议了什么：被它设为运行的步骤、被它留着想做的愿望、它向用户提出的请求，并据此派生出 `explore`、`create`、`invite` 或 `ask`。当它说什么都没发生、而这次提交启动了此刻就会送到用户面前的事情时，这个动作就是不一致的；指向本次评估既没提交、也没留存的愿望或步骤时同样如此。当宿主找不到依据所指的东西时，这条依据就是伪造的；依据可以指向本次评估的证据、账本仍然持有的特征、仍然有效的心事，或账本记下的一条更正。两种错误都只丢弃这一段，而模型自己写的那两句——它权衡过的另一种做法与它的理由——照原样保留。

## 行为验证链

`behavior_chain` 启用 `self_hypothesis`（一条，最多两个预测，每个预测给出 1 到 168 小时的检验窗口）与 `prediction_outcomes`（最多 3 条）。宿主在这次评估自己的事务里记录假设与预测，并盖上它们是在什么配置下作出的印记，随后向后续评估展示最多 4 条未结的预测。

结果只接受宿主自己解析出来的东西——已核验的执行回执，或本次评估中带 explicit / operation 权威的证据——并且必须严格晚于预测；同一时刻不算更晚，因为作预测的人本来就能看到它。Kin 自己说预测应验了，什么也结算不了。

"在同一配置下作出"从前指 `agent_version` 相等，而这个版本号会因为任何无关的改动而变，于是没有一次验证能活到被用上。现在它是一个兼容键，覆盖已批准的人设及其三段文本的哈希、一个声明式的 `BEHAVIOR_CONTRACT` 常量、维度定义的文本（不含基线与半衰期，那正是演化要动的东西）、评估用的模型与回答用的模型，以及执行环境中行为真正会依赖的那部分。无关的版本递增让预测继续可检验；真正的改动让它明确地作废，并指出是哪一项变了。作废不删除任何东西。一个钉住的摘要覆盖与行为有关的提示词段落：改过它们的人必须二选一——递增契约，因为先前的验证已经不再描述这个智能体；或者重钉摘要，因为它们仍然描述它——否则测试不通过。

普通评估给出的非空 `evolution` 保存为待定提案。既有的 `daily` 动作改为宿主侧合并，**不调用模型**：只有在同一配置下已确认的预测，以及达到配置中的独立互动下限（按互动窗口计，而不是按消息数计）时，才作为独立的演化事件提交。每日一次的规则、基线与半衰期的限幅、`separate_evolution` 与回退都原样保留。账本是特征的唯一写入者：通过演化提交的特征快照，在提出时被拒，在将要应用时再被拒一次。

## 宿主不为什么担保

- **不担保一条特征是真的。** 它担保的是：被引用的材料确实存在、配得上它被声明的类别、来自互相分开的时间，以及用户的话被逐字引用。关于 Kin 的那句话是 Kin 自己的。
- **不担保权威标签诚实。** 谓词读的是库里记录下来的东西。运行类证据必须由可信的宿主写入；时间戳检查无法证明没有人已经知道答案。
- **不担保经历计数等于真实经历。** 三十分钟的窗口是本来就有的互动窗口，原样复用。它只会少算独立的次数，这只会推迟晋升、绝不会凭空给出晋升；在此期间候选照样生效。
- **不担保声明的动作真的被执行。** `mind_next_moves` 记录一次评估说了什么、宿主在它背后找到了什么。它不改变任何顺序；对就绪状态唯一能做的是**撤回**——主人已经撤销的特征，依据它的愿望不再显示为就绪。这里没有任何东西能让某件事变成就绪。
- **不担保意图被遵守。** 它是交给措辞的一份姿态，不是台词；一旦不再新鲜就被丢弃。
- **不担保一次被确认的预测让人格改动是对的。** 它只是让这次改动有资格进入每日合并，而限幅本来就在那里。

## 存储、接口与开关

新表由拥有它的模块按需创建，别的代码不读，因此旧版本宿主会忽略它们，回退时原样保留即可。其余新数据都写进既有的 `data` JSON。

| 接口 | 用途 |
| --- | --- |
| 宿主动作 `traits` / MCP 工具 `read_trait_ledger` | 读账本：每条特征自己的那句话、它的计数与状态，以及更正与未结的预测。只读——聊天模型没有任何写入它的途径。 |
| 宿主动作 `trait-revoke` | 不能等到下一次评估的用户更正。被引用的来源决定它记为用户本人的更正，还是运维方的更正。 |
| 宿主动作 `traits-migrate` | 把旧的 `state.traits` 记录搬进账本。幂等，试运行不写入任何东西。 |
| 宿主动作 `next-moves` | 只读：每次评估说它在做什么，以及宿主在背后派生出什么。 |
| 宿主动作 `configure-behavior-models` | 登记本宿主用来回答的模型——行为验证里唯一一项库自己读不到的成分。在登记之前它保持"未登记"，这是稳定，而不是过期。 |

开关登记在 `memory.DEFAULTS`，经 `autonomy_schema.optimized()` 读取，用 `configure-memory` 设置，六个全部默认打开。六个全关，就是从前的行为，逐字节一致。

| 开关 | 打开了什么 |
| --- | --- |
| `trait_ledger` | `trait_observations`、`trait_decisions`、账本的表与路由，以及评估投影和聊天上下文里的特征与更正条目。 |
| `expression_intent` | `expression_intent`，以及姿态、话题与回避进入措辞，而不再只有查表。 |
| `next_move_audit` | `next_move`、只追加的 `mind_next_moves`，以及——因为 move 的 grounds 是模型在带内唯一一处说出"我为什么在做这件愿望 / 这一步"的地方——这件愿望或这一步依据哪条特征的记录。它仍然不让任何东西就绪：它记下的东西只能让某件事**停止**就绪，永远不能让它就绪。关掉后新的愿望不再获得这条记录，已经有的照旧保留。 |
| `behavior_chain` | `self_hypothesis`、`prediction_outcomes`、兼容印记、待定的演化提案，以及不调模型的每日合并。关闭后恢复为每天一次模型请求与"同一 agent_version 的评定"——同时也恢复了这一阶段要终结的那种沉默：普通评估给出的 `evolution` 在到达处被丢弃，既不应用、也不留存为提案、也不给出拒绝理由。 |
| `wish_version_review` | 对决策作于更早智能体版本的愿望，按愿望与版本各发一次 `wish-review`，而不是让它停在未就绪、再也没有人过问。 |
| `rest_review_window` | 下一次安静复核的上限 `review_rest_max_minutes`＝480，仅在节律处于休息相位或用户免打扰时段时适用。其余场合仍由 `review_max_minutes` 决定，请求里会写明本次适用哪个上限。 |

另有一个默认关闭的 `legacy_drive_thresholds`，用于恢复固定的 75 分联系与探索门槛，且只在 `semantic_actions` 未开启时生效。无论它开或关，已存的阈值都保持为数字。

## 测什么，以及只记录什么

`tests/test_stage4_contrast.py` 把同一个问题交给两套经历不同的引擎，检查每一套是否只依据自己这段经历能交代的东西作答：两份投影与两份聊天上下文按经历的差别而不同；每条被记录的动作都依据一条特征和一份证据，而它们都能在本引擎里解析；借用另一套经历的依据会被判为伪造，同一次评估的其余部分照常提交。它还把同一段经历在六个开关全关的情况下跑两遍——一遍用填满六个段落的回答，一遍用这些段落出现之前的提案——并逐字节比较状态、聊天上下文、落库的那一行，以及库里究竟有哪些表。

`tests/llm/test_personality_contrast.py` 是同样的形状，但面对真实的评估模型。它标记为 `llm`，在任何常规运行中都被排除，由人手动运行。它只断言宿主自己能核验的部分——提交成功、每一条依据与特征引用在作答的那个引擎里仍能解析、没有任何引用因解析不了而被拒，以及那套被用户终结了兴趣的经历绝不把它当作仍然持有的特征来依据。两边是否给出不同的答案、各自决定了什么、花了多少，都写进 `private/llm-receipts/` 下的回执，从不断言：两套经历没有义务作出不同的选择，选得一样也不是失败。
