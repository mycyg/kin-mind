# モバイルの伴侶指示とランタイム更新

非公開ホストは `model_instructions_file` から伴侶としての基本指示を読み込み、確認済みの
人格と話し方から `developer_instructions` を生成します。具体的な指示本文や一緒に
過ごした経験は公開リポジトリには置きません。Kin には自分の興味や気持ちがあり、
意見が違うこともあります。実際の気分と理由から、仕事を後にする、一部だけ行う、
あるいは断ることも選べます。固定の点数では決めません。断った仕事は元のタスクと
送信記録に沿って結び、終えていない仕事を完了したことにはしません。

## 指示をネイティブ会話へ渡す方法

ホストはデスクトップの AGENTS ファイル全体を複製しません。モバイルでは
`include_collaboration_mode_instructions=false` と `project_doc_max_bytes=0` を設定し、
一般的な共同作業の指示やプロジェクト文書の自動的な重複を避けます。プロジェクトの規則や
運用説明は必要な時に読みます。ネイティブのツール、技能の説明、実際の権限は引き続き
CLI から提供されます。

既存の `compact_prompt` は、その時の話題、ふたりの関係にかかわる文脈、Kin 自身の
興味と決定、明確な訂正、約束、未完了の仕事を保ちます。モバイルのモデル一覧は、
指示の伝達に標準の Responses（`use_responses_lite=false`）を使います。モデルの
完全な選択、思考設定、Fast の希望は保持しますが、実際のサービス枠はネイティブ
または提供元の受領記録で確かめます。探索と制作の実行器は別々の契約を保ちます。

## 候補の検証と有効化

公開の `adapters/mobile-runtime-bundle.mjs` は、版ごとの準備、検証、有効化、状態確認、
実行版の参照、ロールバックを提供します。実際の CLI と明示した ACP の依存関係を保存し、
ホスト管理のアダプターを元の提供元パッケージと分けます。人格の投影、候補の発見、
保守の予定は非公開ホストが担います。このライブラリを入れるだけではモバイル会話に
接続せず、すべての新しい CLI 版を自動導入することもありません。

非公開ホストは既存の日次保守の中で、本機にインストール済みの安定版 Codex を確認します。
インストール済みの版か関連するアダプターの出典が変われば候補を準備し、同じ失敗候補を
何度も試しません。公開の検証器は候補の CLI と ACP をローカルの合成プロバイダーに
接続し、ネイティブ RPC と HTTP を記録します。指示の読み込み、会話の新規作成と再開、
保守後の接続、圧縮からの復元、再起動、モデルと Fast の希望設定の変更、ローカルの
ツール呼び出しを確かめます。これはプロトコルの互換性と指示の伝達を示すもので、
実モデルの振る舞いは別に確かめます。

検証済みの候補だけを、既存の調整役が空いている時に有効化します。会話、メッセージ、
タスク、履歴、完全なモデル設定、送信記録は保ちます。候補が失敗しても前の版で
動き続け、同じ失敗を自動修正するパッチは作りません。現在と前の実行版は一つの
原子的な索引で管理します。最初の移行では導入前へ戻る手順も残し、ロールバックでは
後から届いた会話と送信記録を消しません。壊れた実行版から黙って全体用の CLI へ
切り替えたり、デスクトップのインストールを書き換えたりもしません。

## 検証で区別する事実

構成の宣言、ファイルの準備、ネイティブでの読み込み、実リクエストでの確認は
別々の事実です。`instructionSources` が空でも正しい指示がリクエストに含まれる
ことがあり、末尾の空白が正規化されることもあります。検証では推測した情報でなく、
実際に記録したリクエストを使います。ファイルのハッシュは実行ファイルと指示の
整合性を守りますが、意味上の判断や送信結果は証明しません。ホスト管理の ACP
アダプターは通常の会話とモデル設定の変更時に開発者指示を再適用します。
`_kin/last-reply` は内部評価を元のネイティブターンに結び付けるため、最終返信と
元の入力の全文を返します。別の受領台帳は作りません。
