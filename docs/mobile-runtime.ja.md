# モバイルの伴侶指示とランタイム更新

非公開ホストは `model_instructions_file` から伴侶としての基本指示を読み込み、確認済みの
人格と話し方から `developer_instructions` を生成します。具体的な指示本文や一緒に
過ごした経験は公開リポジトリには置きません。Kin には自分の興味や気持ちがあり、
意見が違うこともあります。実際の気分と理由から、仕事を後にする、一部だけ行う、
あるいは断ることも選べます。固定の点数では決めません。断った仕事は元のタスクと
送信記録に沿って結び、終えていない仕事を完了したことにはしません。

## 指示をネイティブ会話へ渡す方法

モバイルの app-server は Kin 専用の Codex ホーム `state/codex-home` で動き、デプロイが
`CODEX_HOME` でこれを指定します。デスクトップのホームは読みません。ホストは起動のたびに、
機密を含まないテンプレート、心の設定、チャットの権限からその `config.toml` を作り直し
ます。置くのは記憶ツールのサーバーと任意の computer use だけで、apps、plugins、
マルチエージェント、hooks、ネイティブの memories、技能の説明層は無効です。`auth.json` は
デスクトップのログインへのリンクで、中身は読みません。ホームに `AGENTS.md` があると注入
せずに起動を止めます。`kin-check` は設定のずれ、認証リンクの変化、ホーム内の
`AGENTS.md` や `hooks.json`、会話の作業ディレクトリにある `.codex` のプロジェクト層を
報告します。

ACP の起動設定は、伴侶の基本指示、開発者指示、候補で固定したモデル一覧、
`include_collaboration_mode_instructions=false`、`project_doc_max_bytes=0`、
`compact_prompt` を加え、候補の固定起動スクリプトがすべてのリクエストに効くスイッチを
重ねて指定します。固定したモデル一覧は標準の Responses（`use_responses_lite=false`）を
使い、マルチエージェントの層を加える版の項目を外します。プロジェクトの規則や運用説明は
必要な時に読み、ネイティブのツールと実際の権限は引き続き Codex から提供されます。

`compact_prompt` は、その時の話題、ふたりの関係にかかわる文脈、気持ち、明確な訂正と
約束、Kin 自身の興味と決定、ユーザーの目的と許可された範囲、未完了のタスクごとの番号・
inputVersion・進み具合・次の一歩、そしてどの返信をどの受領記録とともに送ったかを保ちます。
ネイティブの検証は、ローカルのループバック提供元で圧縮のリクエストにこの指示が含まれる
ことを確かめます。提供元の側で行う圧縮はこの検証の範囲外です。セッション管理は圧縮が
完了するたびに、次の送信の前に出典付きのチェックポイントを戻します
（[モバイル会話](mobile-sessions.md)）。

モデルの完全な選択、思考設定、Fast の希望は保持しますが、実際のサービス枠はネイティブ
または提供元の受領記録で確かめます。

## 候補の検証と有効化

公開の `adapters/mobile-runtime-bundle.mjs` は、版ごとの準備、検証、有効化、状態確認、
実行版の参照、ロールバックを提供します。実行版には Codex 本体、許可リストにある依存関係を
含む ACP パッケージ、ホスト管理の ACP の入口が入り、それぞれのハッシュを絶対パスを残さない
マニフェストに記録します。ホスト管理の入口は未改変の提供元の入口から文字列の差分で生成し、
どのアンカーもちょうど一度一致しなければならないため、上流が変わると準備を止めて確認を
待ちます。この入口は、セッション管理が使う `_kin/*` の拡張（実行状態、最後の返信、時間の
上限があり受領記録を `checkOnly` で読み返せる圧縮、チェックポイントの注入、会話の退役、
入力の状態、読み取り専用の評価用の分岐）を加え、毎ターン伴侣の開発者指示を渡します。
このライブラリを入れるだけではモバイル会話に接続せず、Codex の版を導入することも
ありません。

検証はリポジトリ自身の検証器だけを動かし、呼び出し側が渡す証拠は受け付けません。実行版の
ACP と起動スクリプトをモバイルと同じ形（候補の Codex ホームの設定からツールサーバーと
資格情報を除いたもの）で起動してローカルの合成プロバイダーにつなぎ、ネイティブ RPC と
HTTP を記録して、指示の読み込み、会話の新規作成と再開、保守候補、候補の `compact_prompt`
を含む圧縮、再起動、モデル・思考設定・Fast の希望の変更、ローカルのツール呼び出しを
確かめます。リクエストに含めてよいのは、伴侣の基本指示、開発者指示、権限とモデル切り替えの
補足だけで、モデル一覧のテンプレートや `AGENTS.md` は含めません。受領記録はプロトコルの
検証であることを明記し、対象外のもの（実際の提供元へのリクエスト、提供元側の圧縮、ツール
サーバー、資格情報、ホストの起動スクリプト）を並べ、この Codex が ACP パッケージの宣言する
版の範囲に入るかどうかも記録します。

現在と前の実行版は一つの原子的な有効化索引で管理し、現在の版をもう一度有効化しても
何も変わりません。ロールバックは前の検証済みの実行版へ戻しますが、そのスレッドに書き込んだ
版より古い Codex へは、`--allow-downgrade` を付けない限り戻しません。検証に通らない
実行版は起動せず、全体用の CLI へ切り替えたり、デスクトップのインストールを書き換えたり
もしません。

## 毎日の更新

非公開ホストの毎日の点検（launchd のジョブ）は `kin-check` を実行し、通ったインストール
だけを更新します。本機にインストール済みの安定版 Codex と候補の入力の指紋（本体、現在の
実行版の ACP、承認済みの人格、実行版・指示・検証を形づくるソース、固定したモデル一覧）を
現在の候補と比べ、違えば新しい候補を準備して検証します。却下された候補は、入力が変わるか
再試行を求められるまで試さず、失敗した試みは削除せずに脇へ移します。準備は有効化の
指し先を動かさず、何も再起動しません。

検証済みの候補は `kin-deploy runtime-upgrade` を通してだけ有効化します。どちらの
チャンネルにも 15 分間ユーザーの入力がなければ、送信を凍結し、処理中の作業を最大 10 分
待ち、ホストを止め、候補の設定の差分を当て、有効化の指し先を移し、Kin の Codex ホームを
作り直し、ホストを再起動して確かめ（`kin-check`、読み取り専用のツール呼び出し一回、処理中の
入力がないこと）、凍結を解きます。ホストを止めた後のどこかで失敗すれば、設定と前の指し先を
戻してホストを再起動し、ユーザーにシステム通知を送ります。会話の結び付き、履歴、タスク、
受領記録は動かしません。

サービスの起動時、ホストは現在の実行版の Codex を Kin のホームで使って、観測した提供元の
モデル一覧を更新します。結果は次の候補の入力になり、実際に効くのは検証済みの候補が固定した
一覧だけです。制作と探索は現在の実行版の Codex（または明示的に設定した
`native_codex_command`）を使い、Kin のホームがあればそれを使い、それぞれの契約を保ちます。
設定済みの `creation_command` や `exploration_command` を使うのは実行版が入っていない
場合だけで、受領記録はその出所を `legacy-command` と記します。実行版を読めないときは
デスクトップの CLI を使わずに待ちます。

## 検証で区別する事実

構成の宣言、ファイルの準備、ネイティブでの読み込み、実リクエストでの確認は
別々の事実です。`instructionSources` が空でも正しい指示がリクエストに含まれる
ことがあり、ネイティブの読み込みは基本ファイルの前後の空白を取り除きます。検証では
推測した情報でなく実際に記録したリクエストを使い、題名を作るリクエストは、それが仕える
ターンとは別に数えます。ファイルのハッシュは公開するファイルのバイトを守りますが、意味上の
判断や送信結果は証明しません。

本番では、現在の会話に結び付いて完了したゲートウェイのリクエスト、またはメインスレッドに
記録された開発者メッセージとその後のターンが、動いている指示を確かめます。再開したスレッドは、
圧縮か新しいスレッドで文脈が作り直されるまで記録済みの開発者メッセージを保ち、その間ホストは
`developer-differs` を報告します。人格ファイルの検証が通らない、承認記録と違う、または
固定した指示にならないときは、現在の候補が固定した直前の承認済み指示で起動し、ずれを報告
します。新しい人格は新しい候補を通してだけ有効になります。
